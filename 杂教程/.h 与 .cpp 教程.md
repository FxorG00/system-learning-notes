这个问题问到 C++ 的“地基”了。你把这个搞懂，很多 `undefined reference`、`multiple definition`、模板为什么放头文件，都会一下子通。

我们按一个最小项目看。

```text
main.cpp
Student.hpp
Student.cpp
```

`Student.hpp`：

```cpp
#ifndef STUDENT_HPP
#define STUDENT_HPP

class Student {
public:
    static int count;

    Student();
    void say();
};

#endif
```

`Student.cpp`：

```cpp
#include "Student.hpp"
#include <iostream>
using namespace std;

int Student::count = 0;

Student::Student() {
    ++count;
}

void Student::say() {
    cout << "hello" << endl;
}
```

`main.cpp`：

```cpp
#include "Student.hpp"

int main() {
    Student s;
    s.say();
}
```

## 1. `.h` 和 `.cpp` 分别是什么

`.h` / `.hpp` 通常放“声明”。

声明告诉编译器：

```text
有这个类
有这个函数
这个函数长这样
这个变量类型是这样
```

比如：

```cpp
void say();
```

意思是：有个函数叫 `say`，不需要参数，返回 `void`。

`.cpp` 通常放“定义”。

定义是真正实现：

```cpp
void Student::say() {
    cout << "hello" << endl;
}
```

意思是：这个函数具体干什么。

一句话：

```text
.h：告诉别人有什么
.cpp：真正实现它怎么做
```

## 2. `#include "Student.hpp"` 发生了什么

`#include` 不是链接，也不是导入模块。它很粗暴：**文本复制粘贴**。

当 `main.cpp` 写：

```cpp
#include "Student.hpp"
```

预处理器会把 `Student.hpp` 的内容复制到这里。

所以编译器真正看到的 `main.cpp` 大概变成：

```cpp
class Student {
public:
    static int count;

    Student();
    void say();
};

int main() {
    Student s;
    s.say();
}
```

这样编译器就知道：

```cpp
Student
```

是一个类。

```cpp
Student()
```

是构造函数。

```cpp
say()
```

是成员函数。

所以它能检查语法：

```cpp
Student s;
s.say();
```

是否合法。

但注意：此时编译器只知道 `say` 存在，不知道 `say` 的函数体在哪里。

## 3. 编译过程分几步

一般可以理解成四步：

```text
预处理 -> 编译 -> 汇编 -> 链接
```

实际你平时一条命令：

```bash
g++ main.cpp Student.cpp -o app
```

编译器帮你把这些步骤都做了。

### 第一步：预处理

处理：

```cpp
#include
#define
#ifndef
#endif
```

`#include "Student.hpp"` 会被展开成头文件内容。

### 第二步：编译

每个 `.cpp` 会单独编译。

```text
main.cpp      -> main.o
Student.cpp   -> Student.o
```

每个 `.cpp` 都叫一个“翻译单元”。

编译 `main.cpp` 时，编译器看到：

```cpp
Student s;
s.say();
```

它知道有 `Student::say()` 这个声明，所以可以通过编译。

但它会留下一个“未解决的符号”：

```text
我需要 Student::Student()
我需要 Student::say()
```

编译 `Student.cpp` 时，编译器看到真正定义：

```cpp
Student::Student()
Student::say()
int Student::count
```

于是 `Student.o` 里包含这些符号的实现。

### 第三步：链接

链接器把多个 `.o` 拼起来：

```text
main.o + Student.o -> app.exe
```

`main.o` 说：

```text
我需要 Student::Student()
我需要 Student::say()
```

`Student.o` 说：

```text
我这里有 Student::Student()
我这里有 Student::say()
```

链接器把它们对上，程序就生成成功。

## 4. 如果只编译 main.cpp 会怎样

如果你只写：

```bash
g++ main.cpp -o app
```

`main.cpp` 里虽然 include 了 `Student.hpp`，但它没有 `Student.cpp` 的函数实现。

所以链接时会报错：

```text
undefined reference to Student::Student()
undefined reference to Student::say()
```

或者 MSVC 里：

```text
unresolved external symbol
```

意思是：

```text
我知道这个函数存在，因为你声明了。
但我找不到它的实现。
```

## 5. 调用一个函数时发生了什么

看这一句：

```cpp
s.say();
```

编译阶段：

编译器根据头文件声明知道：

```cpp
void Student::say();
```

所以它确认调用合法，并在 `main.o` 里记录：

```text
这里要调用 Student::say()
```

链接阶段：

链接器找到 `Student.o` 里的：

```cpp
void Student::say() {
    cout << "hello" << endl;
}
```

然后把调用地址接上。

运行阶段：

程序执行到：

```cpp
s.say();
```

CPU 跳到 `Student::say()` 那段机器码执行，执行完再回来。

## 6. 为什么头文件里不要随便写函数定义

如果你在 `Student.hpp` 写：

```cpp
void Student::say() {
    cout << "hello" << endl;
}
```

然后多个 `.cpp` 都 include 它：

```text
main.cpp include Student.hpp
Other.cpp include Student.hpp
```

预处理后，两个 `.cpp` 里都会有一份 `Student::say()` 定义。

于是：

```text
main.o 里有 Student::say()
Other.o 里也有 Student::say()
```

链接器会报：

```text
multiple definition of Student::say()
```

意思是：同一个函数被定义了多次。

所以普通函数/普通成员函数通常：

```cpp
// .h
void say();

// .cpp
void Student::say() { ... }
```

如果非要在头文件定义，要加 `inline`，或者写在类内部让它隐式 inline。

## 7. 静态成员为什么要 .cpp 定义

头文件里：

```cpp
class Student {
public:
    static int count;
};
```

这只是声明。

它告诉编译器：

```text
Student 类有一个静态成员 count
```

但没有真正分配内存。

所以 `.cpp` 里要写：

```cpp
int Student::count = 0;
```

这才是定义，给它一块真实存储空间。

如果不写，链接时：

```text
undefined reference to Student::count
```

如果你把它直接写在头文件里：

```cpp
int Student::count = 0;
```

多个 `.cpp` include 后，又会变成多份定义，可能报：

```text
multiple definition of Student::count
```

C++17 可以用：

```cpp
inline static int count = 0;
```

这样可以放头文件。

## 8. 模板为什么常放头文件

普通函数是：

```cpp
// .h
int add(int a, int b);

// .cpp
int add(int a, int b) { return a + b; }
```

编译 `add.cpp` 时，编译器能直接生成 `add(int,int)` 的机器码。

但模板是：

```cpp
template <typename T>
T add(T a, T b) {
    return a + b;
}
```

模板不是一个具体函数。它要等你使用时才知道生成什么版本：

```cpp
add<int>
add<double>
add<string>
```

如果 `main.cpp` 只看到模板声明，看不到模板定义，它没法实例化。

所以模板通常写在头文件里，让使用它的 `.cpp` 能看到完整定义。

## 9. include guard 是干嘛的

头文件通常写：

```cpp
#ifndef STUDENT_HPP
#define STUDENT_HPP

// 内容

#endif
```

这是防止同一个 `.cpp` 里重复包含同一个头文件。

比如：

```cpp
#include "A.hpp"
#include "B.hpp"
```

而 `A.hpp` 和 `B.hpp` 都 include 了 `Student.hpp`。

没有 include guard，`Student` 类可能在同一个 `.cpp` 里被声明两次，报错。

include guard 的意思：

```text
如果 STUDENT_HPP 没定义过，就定义它并包含内容。
如果已经定义过，就跳过。
```

## 10. 一张总图

```text
main.cpp
  #include "Student.hpp"
        |
        v
预处理：把 Student.hpp 复制进 main.cpp
        |
        v
编译 main.cpp -> main.o
main.o 里记录：需要 Student::Student(), Student::say()

Student.cpp
  #include "Student.hpp"
        |
        v
编译 Student.cpp -> Student.o
Student.o 里提供：Student::Student(), Student::say(), Student::count

链接：
main.o + Student.o
        |
        v
找到所有需要的函数和变量定义
        |
        v
生成可执行程序 app
```

最核心一句：

```text
#include 只让当前 .cpp 看见声明；
真正的函数实现要么在头文件里可见，要么通过 .cpp 编译后在链接阶段找到。
```

所以你以后看到报错可以这样判断：

```text
编译错误：多半是声明看不见、语法不对、类型不匹配。
链接错误：多半是声明看见了，但定义没被编译进来，或者定义重复了。
```
