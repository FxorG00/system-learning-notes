在 C++ 中，异常处理通过 `try`、`catch` 和 `throw` 关键字实现。要捕获所有类型的异常，可以使用省略号 `...` 作为参数：

```cpp
try {
    // 可能抛出异常的代码
} catch (...) {
    // 处理任何类型的异常
}
```

### 关键点说明
- `catch(...)` 称为“捕获所有异常”的处理块，它能匹配任意类型的异常（包括整数、字符串、标准异常类对象等）。
- 由于无法获取异常的具体信息，通常在此块内进行通用处理，例如：
  - 记录错误日志
  - 释放资源（如关闭文件、释放内存）
  - 重新抛出异常（`throw;`）让上层继续处理
  - 或者直接终止程序（如调用 `abort()`）

### 示例
```cpp
#include <iostream>
#include <stdexcept>

int main() {
    try {
        // 模拟不同异常
        throw std::runtime_error("运行时错误");
        // throw 42;           // 也可以抛 int
        // throw "字符串";     // 或 const char*
    } catch (const std::exception& e) {
        // 优先捕获标准异常，可获取详细信息
        std::cout << "标准异常: " << e.what() << std::endl;
    } catch (...) {
        // 捕获其他所有非标准异常
        std::cout << "捕获到未知异常" << std::endl;
        // 可以选择重新抛出
        // throw;
    }
    return 0;
}
```

### 注意事项
- `catch(...)` 应放在所有特定 `catch` 块的**最后**，否则它会在前面拦截所有异常，导致后面的特化 `catch` 失效。
- 过度使用 `catch(...)` 可能掩盖编程错误（如数组越界、空指针访问），这些行为在 C++ 中不一定产生异常，而是未定义行为。因此建议只在必要场景（如防止异常逃逸出析构函数、线程入口函数等）中使用。
- 如果需要在 `catch(...)` 中获取异常信息，可以结合 `std::current_exception()` 和 `std::rethrow_exception()` 将异常重新抛出给更具体的处理逻辑。

在 C++ 异常机制中，“标准异常”和“非标准异常”是根据异常类型是否继承自标准库基类 `std::exception` 来区分的：

---

### 标准异常
- **定义**：直接或间接继承自 `std::exception` 类的异常对象。
- **特点**：拥有统一的接口，可通过 `what()` 成员函数获取描述错误的字符串。
- **常见例子**：
  - `std::runtime_error`（运行时错误，如除零、文件打开失败）
  - `std::logic_error`（逻辑错误，如无效参数、越界）
  - `std::bad_alloc`（内存分配失败）
  - `std::out_of_range`、`std::invalid_argument` 等派生类
- **捕获方式**：通常用 `catch(const std::exception& e)` 捕获，并通过 `e.what()` 获取错误信息。

---

### 非标准异常
- **定义**：**不**继承自 `std::exception` 的任何异常类型。
- **特点**：没有统一的接口，无法通过 `what()` 获取信息，只能依赖具体类型处理。
- **常见例子**：
  - 基本类型：`throw 42;`（int）、`throw "error";`（const char*）
  - 自定义类（未继承 `std::exception`）：`throw MyClass();`
  - 指针等：`throw new std::string("oops");`
- **捕获方式**：必须针对具体类型编写 `catch` 块，或使用 `catch(...)` 统一兜底。

---

### 为什么区分？
- **标准异常**推荐用于现代 C++ 编程，因为其语义清晰、便于调试和复用。
- **非标准异常**多见于遗留代码或简单场景，但会降低异常的可移植性和可维护性。
- 使用 `catch(...)` 可以同时覆盖两者，但会丢失具体信息，通常只作为最后防线。
