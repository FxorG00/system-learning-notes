﻿# C++ 友元教程

> 这份专门讲 `friend`。重点解决三个问题：友元是什么、什么时候需要友元、为什么 `cout << obj` 通常要写成非成员友元函数。

## 1. 友元是什么

在 C++ 里，类的 `private` 成员默认只能被这个类自己的成员函数访问。

```cpp
class A {
private:
    int x;

public:
    A(int v) : x(v) {}
};
```

类外普通函数不能直接访问：

```cpp
void print(A a) {
    cout << a.x;   // 错，x 是 private
}
```

如果你把这个函数声明成友元：

```cpp
class A {
private:
    int x;

public:
    A(int v) : x(v) {}

    friend void print(A a);
};

void print(A a) {
    cout << a.x;   // 对，print 是 A 的友元
}
```

友元的意思是：

```text
这个外部函数不是我的成员函数，但我允许它访问我的 private/protected 成员。
```

## 2. 友元不是成员函数

这是最重要的一点。

```cpp
class A {
private:
    int x;

public:
    friend void print(A a);
};
```

`print` 虽然写在类里面声明，但它不是成员函数。

所以调用时不是：

```cpp
A a;
a.print();   // 错
```

而是：

```cpp
A a;
print(a);    // 对
```

友元函数没有 `this` 指针。

成员函数有 `this`：

```cpp
class A {
public:
    void f() {
        // 这里有 this
    }
};
```

友元函数没有：

```cpp
friend void print(A a);
```

它只是被授权访问私有成员的普通函数。

## 3. 为什么需要友元

友元常用于两类场景：

1. 普通函数确实需要访问类的私有数据。
2. 运算符重载的左操作数不是本类对象。

第二类就是你截图那道题的重点。

## 4. 成员函数形式的运算符重载

假设有一个复数类：

```cpp
class Complex {
private:
    double real;
    double imag;

public:
    Complex(double r = 0, double i = 0) : real(r), imag(i) {}

    Complex operator+(const Complex& other) const {
        return Complex(real + other.real, imag + other.imag);
    }
};
```

这里 `operator+` 是成员函数。

表达式：

```cpp
a + b
```

等价于：

```cpp
a.operator+(b)
```

所以成员函数形式有一个特点：

```text
左操作数必须是当前对象 *this。
```

`a + b` 中，左操作数是 `a`，它是 `Complex` 对象，所以可以写成成员函数。

## 5. 为什么 `cout << obj` 通常不能写成成员函数

输出自定义对象时，你希望写：

```cpp
Complex c(1, 2);
cout << c;
```

这个表达式的左操作数是：

```cpp
cout
```

右操作数是：

```cpp
c
```

如果把 `operator<<` 写成 `Complex` 的成员函数，那么调用形式会变成：

```cpp
c.operator<<(cout)
```

对应表达式是：

```cpp
c << cout
```

这不是我们想要的。

我们想要的是：

```cpp
cout << c
```

左边是 `ostream`，不是 `Complex`。

但是你不能去修改标准库里的 `ostream` 类，不能给 `cout` 所属的类添加成员函数。

所以只能写成非成员函数：

```cpp
ostream& operator<<(ostream& os, const Complex& c);
```

这样：

```cpp
cout << c
```

就等价于：

```cpp
operator<<(cout, c)
```

这就是为什么题目选 B：

```text
重载 << 运算符用于输出自定义对象
```

通常必须使用非成员函数。如果这个非成员函数还要访问对象的私有成员，就声明为友元。

## 6. `operator<<` 的标准写法

```cpp
#include <iostream>
using namespace std;

class Complex {
private:
    double real;
    double imag;

public:
    Complex(double r = 0, double i = 0) : real(r), imag(i) {}

    friend ostream& operator<<(ostream& os, const Complex& c);
};

ostream& operator<<(ostream& os, const Complex& c) {
    os << c.real << "+" << c.imag << "i";
    return os;
}
```

使用：

```cpp
Complex c(1, 2);
cout << c << endl;
```

为什么返回 `ostream&`？

因为要支持链式输出：

```cpp
cout << c << endl;
```

它实际相当于：

```cpp
operator<<(operator<<(cout, c), endl);
```

如果不返回 `ostream&`，后面的 `<< endl` 就接不上。

为什么第一个参数是 `ostream&`？

因为输出流对象不能被复制，必须传引用。

为什么第二个参数是 `const Complex&`？

因为输出时不应该修改对象，并且传引用避免复制。

## 7. `operator>>` 的标准写法

输入自定义对象：

```cpp
cin >> c;
```

左操作数是 `cin`，类型是 `istream`，所以也通常写成非成员函数。

```cpp
class Complex {
private:
    double real;
    double imag;

public:
    Complex(double r = 0, double i = 0) : real(r), imag(i) {}

    friend istream& operator>>(istream& is, Complex& c);
    friend ostream& operator<<(ostream& os, const Complex& c);
};

istream& operator>>(istream& is, Complex& c) {
    is >> c.real >> c.imag;
    return is;
}

ostream& operator<<(ostream& os, const Complex& c) {
    os << c.real << "+" << c.imag << "i";
    return os;
}
```

注意 `operator>>` 的第二个参数通常不是 `const`：

```cpp
Complex& c
```

因为输入要修改 `c`。

## 8. 哪些运算符必须是成员函数

有些运算符不能写成友元/非成员，只能写成成员函数。

常见必须是成员函数的有：

```cpp
operator=
operator[]
operator()
operator->
```

所以选项 A：

```text
重载 = 运算符
```

不是“必须使用友元函数”，反而 `operator=` 必须是成员函数。

例子：

```cpp
class A {
public:
    A& operator=(const A& other) {
        if (this != &other) {
            // 复制数据
        }
        return *this;
    }
};
```

## 9. `++` 和 `-` 为什么不一定要友元

### `++` 运算符

前置自增可以写成成员函数：

```cpp
class Counter {
private:
    int value;

public:
    Counter(int v = 0) : value(v) {}

    Counter& operator++() {
        ++value;
        return *this;
    }
};
```

使用：

```cpp
Counter c;
++c;
```

后置自增：

```cpp
class Counter {
private:
    int value;

public:
    Counter(int v = 0) : value(v) {}

    Counter operator++(int) {
        Counter old = *this;
        ++value;
        return old;
    }
};
```

那个 `int` 是哑元参数，用来区分后置 `c++`。

所以 `++` 不必须用友元。

### `-` 运算符

如果是：

```cpp
a - b
```

左操作数是本类对象，可以写成员函数：

```cpp
class Number {
private:
    int value;

public:
    Number(int v = 0) : value(v) {}

    Number operator-(const Number& other) const {
        return Number(value - other.value);
    }
};
```

所以 `-` 也不必须用友元。

## 10. 什么时候用成员，什么时候用非成员

可以用这个判断：

### 适合成员函数

左操作数是本类对象：

```cpp
a + b
a - b
++a
a = b
a[i]
```

成员函数形式：

```cpp
a.operator+(b)
```

### 适合非成员/友元函数

左操作数不是本类对象，或者希望左右操作数地位对称：

```cpp
cout << obj
cin >> obj
3 + obj
```

比如：

```cpp
3 + obj
```

左操作数是 `int`，不是你的类对象，没法写成你的类成员函数。可以写非成员：

```cpp
Number operator+(int lhs, const Number& rhs);
```

如果要访问 `rhs.value`，就声明为友元。

## 11. 友元类

除了友元函数，也可以声明友元类。

```cpp
class A {
private:
    int secret = 42;

    friend class B;
};

class B {
public:
    void show(A a) {
        cout << a.secret << endl;
    }
};
```

这里 `B` 是 `A` 的友元类，所以 `B` 的成员函数可以访问 `A` 的私有成员。

但友元类要慎用，因为权限很大。

## 12. 友元的重要性质

### 12.1 友元关系不双向

```cpp
class A {
    friend class B;
};
```

意思是：`B` 可以访问 `A` 的私有成员。

但不代表 `A` 可以访问 `B` 的私有成员。

```text
A 把 B 当朋友，不代表 B 把 A 当朋友。
```

### 12.2 友元关系不传递

如果：

```text
A 的友元是 B
B 的友元是 C
```

不代表 `C` 是 `A` 的友元。

### 12.3 友元关系不继承

基类的友元不自动成为派生类的友元。

派生类的友元也不自动成为基类的友元。

先记住一句话：

```text
友元权限只对声明它的那个类有效。
```

## 13. 友元破坏封装吗

友元确实会打破一部分封装，因为它允许外部函数访问私有成员。

但它不是“坏东西”。它适合用于：

- `operator<<`
- `operator>>`
- 左操作数不是本类对象的运算符重载
- 两个类关系非常紧密，需要高效访问内部数据

如果普通成员函数或 public 接口能解决，就不必滥用友元。

## 14. 本题为什么选 B

题目：

```text
下列哪种情况必须使用友元函数（或非成员函数）来重载运算符？
```

选项：

```text
A. 重载 = 运算符
B. 重载 << 运算符用于输出自定义对象
C. 重载 ++ 运算符
D. 重载 - 运算符
```

逐个看：

### A. `operator=`

赋值运算符必须是成员函数。

所以不是友元。

### B. `operator<<` 输出对象

想写：

```cpp
cout << obj;
```

左操作数是 `cout`，不是 `obj`。

不能把这个运算符写成 `obj` 的成员函数。

所以要写成非成员函数：

```cpp
ostream& operator<<(ostream& os, const Obj& obj);
```

如果要访问 `obj` 的私有成员，就加 `friend`。

所以 B 对。

### C. `operator++`

通常可以写成员函数。

### D. `operator-`

通常也可以写成员函数。

因此答案是 B。

## 15. 一页速记

```text
friend = 允许外部函数/类访问 private/protected。
友元不是成员函数，没有 this。
operator<< / operator>> 通常写非成员函数。
如果非成员函数要访问私有成员，就声明为 friend。
operator= 必须是成员函数。
左操作数是本类对象：优先考虑成员函数。
左操作数不是本类对象：考虑非成员/友元函数。
友元不双向、不传递、不继承。
```

最常背模板：

```cpp
class A {
private:
    int x;

public:
    A(int v = 0) : x(v) {}

    friend ostream& operator<<(ostream& os, const A& a);
};

ostream& operator<<(ostream& os, const A& a) {
    os << a.x;
    return os;
}
```
