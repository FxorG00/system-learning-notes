# Part 1：一组 parameters 怎样真的学会

## 0. 今天要造什么

我们先造一份没有噪声的数据：

```text
x = [1,2,3,4]
y = [3,5,7,9]
```

真实关系是：

$$
y=2x+1
$$

程序一开始不知道 `2` 和 `1`。它只持有 parameters $w,b$，不断执行：

```text
input x
-> prediction
-> loss
-> gradient
-> update w,b
-> 下一轮 prediction
```

当这条 loop 能从错误参数走向接近 `w=2,b=1`，T4 的 gradient、T6 的 numerical discipline 才第一次变成真正的 training。

## 1. Model：当前 parameters 给出什么预测

Linear model（线性模型）：

$$
\hat y^{(i)}=wx^{(i)}+b
$$

$x^{(i)}$ 是第 $i$ 个 feature，$y^{(i)}$ 是真实 label（标签），$\hat y^{(i)}$ 是 prediction（预测值）。

在 NumPy 中：

```python
def predict(x: np.ndarray, weight: float, bias: float) -> np.ndarray:
    return weight * x + bias
```

若 `weight=0,bias=0`，第一轮 predictions 全为 `0`。Model 只负责根据当前 parameters 计算 output；它不会自己判断好坏，也不会自己更新。

## 2. Loss：把一批错误压成一个可比较的 scalar

每条样本的 error：

$$
e^{(i)}=\hat y^{(i)}-y^{(i)}
$$

Mean squared error（均方误差，MSE）：

$$
J(w,b)
=
\frac{1}{m}
\sum_{i=1}^{m}
\left(\hat y^{(i)}-y^{(i)}\right)^2
$$

$m$ 是 sample count。平方让正负误差不会互相抵消；平均让不同 batch size 的 loss 更容易比较。

有些推导会额外乘 $\frac12$，让求导后的 `2` 抵消；PyTorch `MSELoss(reduction="mean")` 与本课 `mse_loss` 使用上面的普通 mean，不含 $\frac12$。两种 objective 只差常数倍，但公式、gradient、手算 oracle 和代码必须选同一个 convention。

## 3. Gradient：当前参数应该向哪里改

把 prediction 代入：

$$
J(w,b)
=
\frac{1}{m}
\sum_{i=1}^{m}
\left(wx^{(i)}+b-y^{(i)}\right)^2
$$

对 $w$ 求偏导。Squared error 的外层导数带来 `2`，内层对 $w$ 的导数是 $x^{(i)}$：

$$
\frac{\partial J}{\partial w}
=
\frac{2}{m}
\sum_{i=1}^{m}
\left(\hat y^{(i)}-y^{(i)}\right)x^{(i)}
$$

对 $b$ 求偏导，内层对 $b$ 的导数是 `1`：

$$
\frac{\partial J}{\partial b}
=
\frac{2}{m}
\sum_{i=1}^{m}
\left(\hat y^{(i)}-y^{(i)}\right)
$$

单 feature、使用 1-D `features` 时对应：

```python
errors = predictions - targets
grad_weight = 2.0 * np.mean(errors * features)
grad_bias = 2.0 * np.mean(errors)
```

多 feature 时不能直接让 `[m]` errors 与 `[m,n]` features 相乘；第 6 节会把它写成 `features.T @ errors`。

T4 的 computation graph 在这里具体落地：`errors` 是 upstream signal，`features` 是 prediction 对 weight 的 local derivative。

## 4. Update：沿负 gradient 迈一步

Gradient 指向 loss 增长最快的方向，所以 gradient descent（梯度下降）沿反方向更新：

$$
w\leftarrow w-\alpha\frac{\partial J}{\partial w}
$$

$$
b\leftarrow b-\alpha\frac{\partial J}{\partial b}
$$

$\alpha$ 是 learning rate（学习率），控制本轮走多远。

更新必须使用同一轮 forward 得到的两个 gradients：

```python
new_weight = weight - learning_rate * grad_weight
new_bias = bias - learning_rate * grad_bias
weight, bias = new_weight, new_bias
```

若先更新 `weight` 再用新 `weight` 计算 `grad_bias`，两个参数就不再来自同一个 objective state。

## 5. 手推第一轮

使用：

```text
x = [1,2]
y = [3,5]
w = 0
b = 0
```

Predictions：

$$
\hat{\mathbf y}=[0,0]
$$

Errors：

$$
\mathbf e=[-3,-5]
$$

Gradient：

$$
\frac{\partial J}{\partial w}
=
\frac{2\left[(-3)\cdot1+(-5)\cdot2\right]}{2}
=-13
$$

$$
\frac{\partial J}{\partial b}
=
\frac{2(-3-5)}{2}
=-8
$$

若 $\alpha=0.1$：

$$
w_{\text{new}}=0-0.1(-13)=1.3
$$

$$
b_{\text{new}}=0-0.1(-8)=0.8
$$

两者都向真实值靠近。这个手算值应成为程序第一轮的 exact oracle，而不是只观察训练几百轮后“看起来差不多”。

## 6. 多特征时 shape 怎样变化

若每个 sample 有 $n$ 个 features：

```text
X [m,n]
w [n]
b scalar
y_hat [m]
errors [m]
```

Forward：

$$
\hat{\mathbf y}=X\mathbf w+b
$$

Gradient：

$$
\nabla_{\mathbf w}J
=
\frac{2}{m}X^T(\hat{\mathbf y}-\mathbf y)
$$

$$
\frac{\partial J}{\partial b}
=
\frac{2}{m}\sum_i(\hat y^{(i)}-y^{(i)})
$$

T7 可以先做单 feature，再扩到 multi-feature。两者使用同一条 loop，区别只是 parameter shape 与 matmul。

# Part 2：实现一个可验证的 training loop

## 7. Public functions

文件：`linear_regression_numpy.py`

```python
def predict(
    features: np.ndarray,
    weights: np.ndarray,
    bias: float,
) -> np.ndarray:
    ...


def mse_loss(
    predictions: np.ndarray,
    targets: np.ndarray,
) -> float:
    ...


def gradients(
    features: np.ndarray,
    targets: np.ndarray,
    weights: np.ndarray,
    bias: float,
) -> tuple[np.ndarray, float]:
    ...


def train(
    features: np.ndarray,
    targets: np.ndarray,
    learning_rate: float,
    steps: int,
) -> tuple[np.ndarray, float, list[float]]:
    ...
```

这里规定 observable behavior，不规定你要不要拆更多 helpers。

Input contract：

```text
features [m,n]，float64，m>0，n>0
targets [m]，float64
values finite
learning_rate > 0 且 finite
steps > 0
```

Output contract：

```text
prediction shape [m]
gradient weights shape [n]
loss 是 finite scalar
history 每一步记录一个 loss
caller input 不被修改
```

## 8. 固定 synthetic data

```python
rng = np.random.default_rng(2026)
features = rng.normal(size=(128, 2))
true_weights = np.array([2.0, -3.0], dtype=np.float64)
true_bias = 0.5
targets = features @ true_weights + true_bias
```

先不加 noise。无噪声数据让 correctness 更容易定位；加入 noise 后，learned parameters 本来就不应和 true parameters exact equal。

最低 evidence：

```text
第一轮 gradient 与手算/独立 formula 对照
initial loss > final loss
learned weights/bias 接近 true values
final predictions 接近 targets
shapes 与 finite invariants 成立
```

# Part 3：用证据判断 training 是否真的正确

## 9. Loss 下降不是充分证据

以下 bug 仍可能让 loss 下降：

```text
gradient 少乘一个常数，但 learning rate 恰好补偿
只更新 bias，数据又很简单
target/prediction 发生错误 broadcasting
训练和检查都复用了同一条错误公式
```

因此至少使用三层 evidence：

```text
local：第一轮 gradient 对照
trajectory：loss 总体下降且 finite
end state：parameters 与 predictions 接近已知答案
```

T4 的 finite difference 还可以抽查 $w,b$ gradient。它与 analytic gradient 不共享导数公式，是更强的 local oracle。

## 10. Learning rate experiment

保持 dataset、initial parameters 和 steps 相同，只改变：

```text
too small
reasonable
too large
```

观察：

```text
too small：loss 降，但给定 steps 内很慢
reasonable：稳定靠近最低点
too large：震荡、升高，甚至 non-finite
```

不要把“loss 每一步必须严格下降”写成通用 assertion。对当前 full-batch quadratic case，合理 learning rate 下通常很平滑；以后 mini-batch training 本来就会抖动。

## 11. Feature scale 为什么改变优化难度

若一列 feature 范围在 `0~1`，另一列在 `0~10000`，同一个 learning rate 对不同 weight coordinates 造成的有效步长差别很大。Loss surface 会呈狭长形，gradient descent 容易来回震荡。

Standardization（标准化）：

$$
x_j'
=
\frac{x_j-\mu_j}{\sigma_j}
$$

它不改变“线性模型能表达什么”这一事实，却改变 optimization geometry（优化几何），让统一 learning rate 更容易工作。

Scaling parameters 必须只从 training data 估计。T8 会把这条纪律放进 train/validation/test workflow。

## 12. Model、loss 与 optimizer 的边界

```text
model：parameters -> predictions
loss：predictions + targets -> scalar quality signal
optimizer/update rule：gradients + state -> new parameters
```

当前 NumPy 程序可以把三者写在一个文件，但概念边界不能混。PyTorch 中它们会变成不同 objects；serving 只需要 model forward，不需要 targets、loss 或 optimizer。

## 13. 与 AI Infra 的连接

Training：

```text
batch input
-> forward
-> loss
-> backward/gradient
-> optimizer state update
-> new parameters
```

Inference：

```text
input
-> forward
-> output
```

因此 checkpoint 用于 serving 时，通常只需要 parameters/buffers 与 schema，不需要训练 batch、loss history 或 optimizer state。若要 resume training，optimizer state 又可能是必要 artifact。

T7 的 tiny reference 还建立一个长期纪律：优化 kernel、fusion 或 distributed training 后，fast implementation 必须和清晰 reference 在 shape、value 与 update semantics 上对齐。
