# Part 1：服务加载的究竟是什么

## 0. 从一个部署问题出发

训练结束后，我们想在另一个 process 中继续得到相同 output。只保存 Python object 的名字不够，只保存一堆无名 Tensor 也不够。程序必须知道：

```text
model 由哪些 submodules 组成
哪些 Tensors 是 trainable parameters
哪些 Tensors 是持久 state，但不参与梯度
forward 怎样执行
哪些 state 要写入 checkpoint
inference 时哪些开关必须切换
```

PyTorch 用 `nn.Module` 把这些责任组织成一棵有名字的 object tree。

今天造一个小 Module，然后完整走一遍：

```text
construct
-> inspect registered state
-> forward
-> train/eval behavior
-> save state_dict
-> construct fresh object
-> load
-> inference output 对照
```

## 1. 最小 Module 先长什么样

```python
import torch
from torch import nn


class TinyClassifier(nn.Module):
    def __init__(self, input_dim: int, hidden_dim: int, class_count: int) -> None:
        super().__init__()
        self.linear1 = nn.Linear(input_dim, hidden_dim)
        self.activation = nn.ReLU()
        self.dropout = nn.Dropout(p=0.25)
        self.linear2 = nn.Linear(hidden_dim, class_count)

        self.register_buffer(
            "input_scale",
            torch.ones(input_dim, dtype=torch.float32),
        )

        self.debug_tensor = torch.zeros(1)

    def forward(self, inputs: torch.Tensor) -> torch.Tensor:
        scaled = inputs * self.input_scale
        hidden = self.activation(self.linear1(scaled))
        hidden = self.dropout(hidden)
        return self.linear2(hidden)
```

Forward shape：

```text
inputs [B,input_dim]
-> linear1 [B,hidden_dim]
-> ReLU [B,hidden_dim]
-> Dropout [B,hidden_dim]
-> linear2 [B,class_count]
```

先看到 concrete object，再命名：

- 整个 `TinyClassifier` 是 module（可组合模型单元）；
- `linear1` 等是 submodules（子模块）；
- `weight/bias` 是 parameters（由训练更新的注册 Tensor）；
- `input_scale` 是 buffer（随模型保存/移动、但不是 parameter 的 state）；
- forward 中的 `hidden` 是 activation（本次执行产生的中间值）。

`debug_tensor` 只是普通 Tensor attribute。它不会因为“挂在 Module 上”就自动获得 parameter/buffer 的全部行为。

## 2. Module 是一棵注册树

执行：

```python
self.linear1 = nn.Linear(...)
```

不是普通 assignment 那么简单。`nn.Module.__setattr__` 会识别被赋值的 Module/Parameter，并把它注册进当前 object。

因此：

```python
for name, module in model.named_modules():
    print(name, type(module).__name__)

for name, parameter in model.named_parameters():
    print(name, tuple(parameter.shape))
```

能递归看到稳定 names：

```text
linear1.weight
linear1.bias
linear2.weight
linear2.bias
```

这些 names 同时成为 `state_dict` schema 的一部分。重命名 attribute 可能导致旧 checkpoint strict load 失败；它不是纯代码风格修改。

## 3. 为什么调用 `model(inputs)`，而不是直接 `forward`

`forward` 描述模型本身的 calculation。`nn.Module.__call__` 在外面负责 framework behavior，然后再调用 `forward`，例如 hooks 与 mode/autograd 相关处理。

正常写法：

```python
outputs = model(inputs)
```

不要在业务代码中直接调用：

```python
outputs = model.forward(inputs)
```

后者可能绕过 framework 在 `__call__` 周围提供的机制。

## 4. 四类对象不要混在一起

### Module object

Python 侧的结构、submodules、names、mode 与 forward behavior。

### Parameter Tensor

注册的 trainable state。默认出现在：

```python
model.parameters()
model.named_parameters()
model.state_dict()
```

### Buffer

随 Module state 保存/移动，但通常不由 optimizer 更新。例如 BatchNorm running statistics。

### Activation

一次 forward 根据 inputs 与 state 临时产生。它通常不在 `state_dict`，training backward 可能暂时保存它，inference request 结束后即可释放。

Checkpoint（检查点）是持久化 artifact，常以 `state_dict` 为核心。它不是正在运行的 Module object，也不包含任意 Python control flow。

## 5. Parameter、buffer 与普通 Tensor attribute

对上面的 model：

```python
parameter_names = dict(model.named_parameters()).keys()
buffer_names = dict(model.named_buffers()).keys()
state_keys = model.state_dict().keys()
```

应观察：

```text
linear weights/biases -> parameters + state_dict
input_scale           -> buffers + state_dict
debug_tensor          -> neither
```

若 buffer 只想随 device 移动、不想写入 checkpoint：

```python
self.register_buffer("temporary", value, persistent=False)
```

Persistent（持久）只决定是否进入 `state_dict`；它不把 buffer 变成 parameter。

## 6. `state_dict` 是 named Tensor mapping

```python
state = model.state_dict()
for name, tensor in state.items():
    print(name, tensor.shape, tensor.dtype)
```

它保存 registered parameters 与 persistent buffers，key 来自 module tree path。

重要边界：`state_dict()` 返回的是 shallow mapping，values 与当前 module state 有 relation。若要在内存中冻结“当前 best state”，应 deep-copy：

```python
import copy

best_state = copy.deepcopy(model.state_dict())
```

仅写：

```python
best_state = model.state_dict()
```

不能可靠表达“以后 parameters 更新也不影响这个 snapshot”。

# Part 2：Mode 与 gradient recording 是两条轴

## 7. `train()` / `eval()` 改变谁的 behavior

Module 默认处于 training mode：

```python
model.training is True
```

```python
model.eval()
```

递归把 mode 切成 evaluation。真正改变 forward behavior 的是读取 `self.training` 的 layers，例如：

```text
Dropout
BatchNorm
自定义依赖 mode 的 Module
```

`Linear` 与 `ReLU` 通常在两种 mode 下行为相同。

Dropout 的 deterministic probe：

```python
model.train()
train_a = model(inputs)
train_b = model(inputs)

model.eval()
eval_a = model(inputs)
eval_b = model(inputs)
```

在固定 state/input 下：

```text
train_a 与 train_b 可能不同
eval_a 与 eval_b 应相同
```

## 8. `inference_mode()` 控制 autograd-related execution

```python
with torch.inference_mode():
    outputs = model(inputs)
```

它关闭本段 inference 中的 gradient tracking，并允许更强的 inference optimization。它不会自动调用 `model.eval()`。

同样：

```python
model.eval()
```

不会自动关闭 autograd recording。

正常 inference boundary：

```python
model.eval()
with torch.inference_mode():
    outputs = model(inputs)
```

两者分别回答：

```text
eval：Module 应采用哪种行为
inference_mode：本次 execution 是否需要 autograd metadata
```

## 9. 四种组合亲自跑一次

对同一 model/input：

```text
train + grad enabled
train + inference_mode
eval  + grad enabled
eval  + inference_mode
```

记录：

```text
model.training
output.requires_grad
相同 input 重复两次是否 exact equal
```

它会直接证明 mode 与 gradient recording 不是同一个开关。

# Part 3：Checkpoint round trip

## 10. Save：保存 state，不保存本次 activation

```python
checkpoint_path = "tiny_classifier.pt"
torch.save(model.state_dict(), checkpoint_path)
```

文件包含 named parameter/buffer payload。它不保存当前 input、hidden activation、optimizer（除非另行保存），也不自动保存 constructor arguments。

因此 model architecture/config 必须来自：

```text
代码版本
明确 config
artifact metadata
```

## 11. Load：先构造 compatible object

```python
loaded_model = TinyClassifier(
    input_dim=input_dim,
    hidden_dim=hidden_dim,
    class_count=class_count,
)

state = torch.load(
    checkpoint_path,
    map_location="cpu",
    weights_only=True,
)
loaded_model.load_state_dict(state, strict=True)
loaded_model.eval()
```

`map_location="cpu"` 让 artifact 先进入最通用 baseline device；服务再按部署配置显式移动。

`strict=True` 要求 keys 对齐。Missing/unexpected keys 不是默认忽略的小事，而是 checkpoint schema 与 code schema 不一致的信号。

## 12. Round-trip evidence

在保存前先得到 reference：

```python
model.eval()
with torch.inference_mode():
    expected = model(inputs).clone()
```

加载 fresh object 后：

```python
loaded_model.eval()
with torch.inference_mode():
    actual = loaded_model(inputs)

torch.testing.assert_close(actual, expected)
```

这个 evidence 证明：

```text
当前 architecture/config 可重建
state_dict keys compatible
parameter/buffer values 恢复
相同 mode/input 下 output 对齐
```

它不证明 artifact 在另一 PyTorch version、另一 operator backend 或任意 hardware 上 bitwise identical。

## 13. `Module.to` 与 `Tensor.to` 的重要差别

Tensor：

```python
converted = tensor.to(dtype=torch.float64)
```

应接住返回值；转换时通常得到新 Tensor。

Module：

```python
model.to(device="cpu", dtype=torch.float32)
```

会原地转换 registered parameters/buffers，并返回 `self`。普通 `debug_tensor` 不会像 registered state 一样自动跟随。

这正是为什么 serving state 应正确注册，而不是把重要 Tensor 随便挂成普通 attribute。

# Part 4：今日综合程序

## 14. `module_inference.py` 的完整顺序

1. 固定 seed，构造 `TinyClassifier`。
2. 打印 module tree、parameter names、buffer names、state keys。
3. 证明普通 Tensor attribute 不在 registered state。
4. 运行四种 mode/grad combinations。
5. 保存 `state_dict`。
6. 构造 fresh model 并 strict load。
7. 在 `eval + inference_mode` 下对照 outputs。
8. 故意用不兼容 class count 构造一次 fresh model，确认 strict mismatch 被捕获。
9. 正常完成打印：

```text
T10 MODULE INFERENCE PASS
```

Expected strict failure 要捕获具体 `RuntimeError`，确认发生后继续。Unexpected failure 必须 non-zero exit。

## 15. Input 与 output contract

固定 input：

```python
inputs = torch.tensor(
    [
        [1.0, 2.0, 3.0, 4.0],
        [-1.0, 0.5, 2.0, -0.5],
    ],
    dtype=torch.float32,
)
```

建议 dimensions：

```text
input_dim=4
hidden_dim=6
class_count=3
output shape [2,3]
```

Assertions：

```text
output shape/dtype/device exact
all output finite
state keys exact
round-trip output close
eval repeat deterministic
inference output requires_grad == False
```

不需要 pytest、benchmark 或训练 loop。今天验证的是 object/state/inference boundary。

## 16. Save/Load 的安全边界

只加载可信 artifact。Serialization format 与 model file 都可能成为攻击面。优先保存/load state weights，使用当前 PyTorch 推荐的 restricted loading options；不要从陌生来源执行任意 pickle payload。

生产 artifact 还应包含或关联：

```text
model/config version
input schema
dtype policy
class/token mapping
framework/build version
checksum
evaluation evidence
```

这些 metadata 不全都塞进 `state_dict`，但部署系统必须有地方管理。

## 17. 与 AI Infra 的连接

### Replica state ownership

多个 serving replicas 通常各自持有一份 loaded model state。参数 bytes、buffers 与 device placement 决定 baseline memory。

### Inference correctness

忘记 `eval()` 可能让 Dropout/BatchNorm 行为错误；忘记关闭 gradient tracking 会保存无用 metadata、增加 memory/cost。它们是 correctness 与 resource boundary，不只是 style。

### Artifact schema

`state_dict` key names 来自 module tree。Code refactor、module rename 与 shape change都可能造成 schema migration。

### Load pipeline

```text
artifact bytes
-> checksum/version validation
-> CPU deserialize
-> construct compatible Module
-> strict state load
-> device/dtype placement
-> eval
-> warmup
-> ready
```

T10 的小程序覆盖其中核心 object/state steps。后续 inference project 会加并发、batching 与 lifecycle。
