### 1.1 什么是 L1/L2 norm

`norm` 就是“范数”，先把它理解成：**一个向量有多大、多长**。

对于向量：

$$
x = (x_1, x_2, \dots, x_n)
$$

常见两种量法。

`L1 norm`：每个分量取绝对值，再相加。

$$
\lVert x \rVert_1 = \sum_{i=1}^{n} |x_i|
$$

`L2 norm`：每个分量平方、相加、开根号。它就是平面/空间里熟悉的欧几里得长度。

$$
\lVert x \rVert_2 = \sqrt{\sum_{i=1}^{n}x_i^2}
$$

例如：

$$
x=(3,-4)
$$

```text
L1 norm = |3| + |-4| = 7
L2 norm = sqrt(3² + (-4)²) = 5
```

Python 里：

```python
x = np.array([3.0, -4.0])

np.linalg.norm(x, ord=1)  # 7.0，L1 norm
np.linalg.norm(x, ord=2)  # 5.0，L2 norm；ord=2 也是默认值
```

先记这层就够：

```text
L1：把各维“距离”直接相加
L2：直线距离 / 向量长度
```

后面会看到它们用于衡量误差、限制参数大小。特别是常见的 `L2 regularization`，通常会惩罚过大的参数；`L1 regularization` 则更容易让一部分参数变成 `0`。

## 2. 先固定二维 matrix multiplication

设：

$$
A\in\mathbb R^{M\times K},\qquad
B\in\mathbb R^{K\times N}
$$

那么：

$$
C=AB\in\mathbb R^{M\times N}
$$

每个 output element 是：

$$
C_{ij}=\sum_{k=0}^{K-1}A_{ik}B_{kj}
$$

因果链：

```text
选择 output row i
-> 取 A 的第 i 行
-> 选择 output column j
-> 取 B 的第 j 列
-> 沿长度 K 做乘加 reduction
-> 得到 C[i,j]
```

`reduction` 中文常译为归约，表示把一组 values 合成更少的 values。这里 $K$ 个乘积被 sum 成一个 output value，所以 $K$ 不出现在 result shape 中。

### 必看：我感觉 numpy 的 ndarray 对类型的要求不是很严格？

你的直觉基本对，但最好分成两件事看：`data` 的转换，和 `shape` 参数的解析。它们看起来都“很宽松”，其实不是同一种机制。

Python 本身是动态类型语言。NumPy 的很多函数会声明参数可以是 `array_like`，意思是“像数组的数据”：例如 `list`、`tuple`、已有的 `ndarray`，有时还包括其他实现数组协议的对象。

```python
import numpy as np

a = np.asarray([1, 2, 3])        # list -> ndarray
b = np.asarray((1, 2, 3))        # tuple -> ndarray
c = np.asarray([[1, 2], [3, 4]]) # nested list -> 2-D ndarray

print(c.shape)  # (2, 2)
```

概念上，许多 NumPy API 内部会做类似这件事：

```text
Python list / tuple / ndarray
        |
        v
转换或规范化为 ndarray
        |
        v
检查 dtype、shape、维度数等条件
        |
        v
进入底层的 C/CPU 运算实现
```

所以你可以这样理解：很多 NumPy 函数确实会在入口处“接住”`list`/`tuple` 并转换，但它不是完全不管类型，而是先把输入规范成适合计算的数组。

例如 `np.matmul` 接受 `array_like`：

```python
np.matmul([[1, 2]], [[3], [4]])
# array([[11]])
```

但纯 Python 的 `list` 没有定义 `@`：

```python
[[1, 2]] @ [[3], [4]]
# TypeError
```

因为 `@` 是 Python 的运算符；左侧的 `list` 不会处理矩阵乘法。若左边已经是 `ndarray`，则会进入 NumPy：

```python
np.array([[1, 2]]) @ [[3], [4]]
# array([[11]])
```

这里右边的 list 会被 NumPy 转成适合 `matmul` 的数组。

`shape` 又是另一种情况。它通常不是“把 tuple 转成 ndarray”，而是函数把它当作“整数维度序列”来解析：

```python
np.zeros((2, 3))  # tuple：创建 2 x 3
np.zeros([2, 3])  # list：也可以
np.zeros(6)       # 单个 int：创建 shape 为 (6,)
```

它们表达的语义分别是：

```text
(2, 3) 或 [2, 3]
-> 第 0 维长度为 2，第 1 维长度为 3

6
-> 只有一维，长度为 6
```

tuple 常见只是因为它不可变，很适合表达“这个数组的固定 shape”；不是因为 NumPy 只能接受 tuple。

但“宽松”有边界。比如 shape 的每项仍必须是合法的非负整数：

```python
np.zeros((2.5, 3))  # 不合法
np.zeros(("2", 3))  # 不合法
```

数据转换也会发生 dtype 推导：

```python
np.asarray([1, 2.5])    # float64，int 被提升为 float
np.asarray([True, 2])   # int，True 变成 1
np.asarray([1, "hello"])  # Unicode string array
```

核心约束是：普通 `ndarray` 的元素通常有一个统一的 `dtype`。NumPy 会尝试找到能容纳全部元素的共同类型；这也是它能高效地把整块内存交给底层循环或 SIMD/GPU 的原因。

还有一个很重要的坑：嵌套 list 必须规则，才能自然变成多维数组。

```python
np.asarray([[1, 2], [3, 4]])  # shape (2, 2)，规则

np.asarray([[1, 2], [3]])     # 不规则，通常直接 ValueError
```

最后区分 `np.array` 和 `np.asarray`：

```python
np.array(x)    # 默认倾向创建新数组/复制
np.asarray(x)  # 若 x 已经是兼容的 ndarray，尽量直接复用，不复制
```

在你后面做 AI Infra 时，`np.asarray` 的“尽量不复制”特别值得敏感：它可能决定数据只是多一个 Python 视图，还是实际分配并搬运了一整块内存。

一句话压缩：

```text
NumPy 的很多 API 接受 array_like，并会在入口把数据规范化成 ndarray；
shape 参数则被解析为“整数维度序列”。
它灵活，但仍受 dtype、规则 shape、API contract 和是否发生 copy 的约束。
```

# Part 2：统一解释 1-D、N-D 与 broadcasting

## R1 后总览：非 2-D 的矩阵乘法

这是 `np.matmul` / `@` 从二维矩阵乘法推广到 N-D 的规则：

```text
前面的维度：batch dimensions，按 broadcasting 对齐
最后两个维度：真正做矩阵乘法
```

也就是：

```text
(..., M, K) @ (..., K, N)
-> (..., M, N)
```

其中：

```text
K：必须相同的 inner dimension
...：batch dimensions，遵循 NumPy broadcasting
```

例如：

```python
a.shape == (2, 3, 4)
b.shape == (2, 4, 5)

a @ b 的 shape == (2, 3, 5)
```

可以把它想成：有 `2` 组独立的矩阵乘法。

```text
a[0]: (3, 4) @ b[0]: (4, 5) -> (3, 5)
a[1]: (3, 4) @ b[1]: (4, 5) -> (3, 5)

合起来 -> (2, 3, 5)
```

前面的 batch 维还可以广播：

```python
a.shape == (10, 3, 4)
b.shape == (4, 5)

a @ b 的 shape == (10, 3, 5)
```

这里同一个 `(4, 5)` 的 `b` 被用于 10 组 `(3, 4)` matrices。

向量是两个特殊规则：

```text
(K,) @ (K,)    -> ()      点积，得到 scalar
(M, K) @ (K,)  -> (M,)    右边向量
(K,) @ (K, N)  -> (N,)    左边向量
```

机械推导顺序：

```text
1. 先看最后两维能否组成 (M, K) @ (K, N)
2. 再看前面的 batch dimensions 能否 broadcasting
3. 输出 = broadcast 后的 batch shape + (M, N)
4. 如果某边原本是 1-D vector，按向量特例移除对应的临时 matrix axis
```

一句压缩记忆：

```text
matmul = 最后两维做矩阵乘；前面所有维度只是“这一批要做多少次矩阵乘”。
```

### 本次 R1 的真实 baseline

## 8. 为什么 1-D operands 是特例

二维 rule 假设每个 operand 都明确拥有 row axis 与 column axis。但 shape `(K,)` 只有一个 axis，NumPy 必须先决定它在这次 `matmul` 中扮演什么角色。

`np.matmul` 的规则是：

```text
left 是 1-D：临时把它当成 shape (1,K)，计算后移除前面的 1
right 是 1-D：临时把它当成 shape (K,1)，计算后移除后面的 1
```

因此：

| left | right | 临时 core | result |
|---|---|---|---|
| `(K,)` | `(K,)` | `(1,K) @ (K,1)` | `()` |
| `(M,K)` | `(K,)` | `(M,K) @ (K,1)` | `(M,)` |
| `(K,)` | `(K,N)` | `(1,K) @ (K,N)` | `(N,)` |
| `(M,K)` | `(K,N)` | 不需要临时补 axis | `(M,N)` |

`()` 表示 0-D result shape。两个 1-D vectors 使用 `@` 得到 scalar-like result，不是 shape `(1,)` 的 vector。

这也解释了 T2 的边界：1-D ndarray 本身没有固定 row/column orientation；它在 `matmul` 中的角色由 operand position 决定。

官方查证：[`numpy.matmul`](https://numpy.org/doc/stable/reference/generated/numpy.matmul.html)，查看 1-D operands 的 prepend/append/remove 规则。

## 9. N-D matmul 先拆 core，再看 batch

对 rank 至少为 2 的 operands，把 shape 拆成：

$$
\begin{aligned}
\operatorname{shape}(\text{left})  &= [\text{left batch},\ldots,M,K] \\
\operatorname{shape}(\text{right}) &= [\text{right batch},\ldots,K,N]
\end{aligned}
$$

术语：

- `core dimensions`：最后两轴承担一次 matrix multiplication 的角色。
- `inner dimension`：两个 core 中必须匹配的 $K$。
- `batch dimensions`：最后两轴之前的所有 axes，表示并行处理多少组 matrices。

处理顺序：

```text
完整 shapes
-> 拆出最后两轴 core
-> 检查 inner K
-> 单独处理前面的 batch shapes
-> 每个 batch position 做一次 [M,K] @ [K,N]
-> 拼成最终 result
```

同 batch 的例子：

```text
left:  [5,2,3]
right: [5,3,4]

batch: [5] 与 [5]
core:  [2,3] @ [3,4]
result:[5,2,4]
```

这不是一个三维矩阵乘法。它可以理解成 5 组独立的二维 matrix multiplication。

```mermaid
flowchart LR
    L[full operand shapes] --> C[split last two axes as core]
    C --> K[check inner K]
    K --> B[resolve leading batch shapes]
    B --> M[run one matmul per batch position]
    M --> O[assemble output shape]
```

## 10. ordinary broadcasting 的规则

`broadcasting` 中文通常叫广播。它让不同 shapes 在满足规则时参与同一个 array operation，而不要求用户先显式复制成完全相同的 shape。

比较两个 shapes 时，从最右 axis 开始。对应 axis compatible，当且仅当：

```text
两个 sizes 相等
或其中一个 size 是 1
或一边缺少这个 axis，缺失按 size 1 处理
```

result 在每个 axis 上取兼容后的较大 size。

例 1：

```text
left:  (2,1,5)
right:   (3,5)

右对齐：
(2,1,5)
(1,3,5)

5 与 5 compatible
1 与 3 compatible
2 与 1 compatible
result: (2,3,5)
```

例 2：

```text
left:  (2,1,5)
right:   (1,4)

右对齐：
(2,1,5)
(1,1,4)

最右的 5 与 4 不相等，且都不是 1
因此 illegal
```

“size 1 被扩展”是理解语义的模型，通常不表示 NumPy 先真实复制出一整个大 array。后续做 AI memory estimate 时，要区分 logical shape 与 physical materialization。

官方查证：[NumPy Broadcasting](https://numpy.org/doc/stable/user/basics.broadcasting.html)，只看 general rules 与合法/非法 shape examples。

## 11. matmul 只对 batch dimensions 使用 broadcasting

现在把两条规则组合：

```text
最后两轴：按 matrix core 规则处理
前导 axes：按 ordinary broadcasting 处理
```

例 1：

```text
left:  (1,2,3) -> batch=(1), core=(2,3)
right: (7,3,4) -> batch=(7), core=(3,4)

inner: 3 == 3
batch: (1) 与 (7) -> (7)
core output: (2,4)
final: (7,2,4)
```

若 inputs 全是 `1.0`，每个 output element 是 3 个 `1.0 * 1.0` 的和，所以 value 是 `3.0`。

例 2：

```text
left:  (2,1,2,3) -> batch=(2,1), core=(2,3)
right: (1,5,3,4) -> batch=(1,5), core=(3,4)

batch: (2,1) 与 (1,5) -> (2,5)
core output: (2,4)
final: (2,5,2,4)
```

例 3：

```text
left:  (2,2,3) -> batch=(2), core=(2,3)
right: (3,3,4) -> batch=(3), core=(3,4)

inner 3 匹配
但 batch 2 与 3 不相等，且都不是 1
因此 illegal
```

这里最容易犯的错误，是看到 core $K$ 匹配就宣布整个 operation 合法。N-D `matmul` 同时要求 core 可乘、batch shapes 可 broadcast。

## 12. 一条固定的 shape 推导流程

以后看到 `left @ right`，按同一个顺序：

```text
1. 写完整 operand shapes
2. 先处理 1-D operand 特例
3. 标出 matrix core
4. 检查 inner dimensions
5. 提取 batch dimensions
6. 从右向左 broadcast batch dimensions
7. 拼接 broadcasted batch 与 core output [M,N]
8. 最后运行 NumPy 确认
```

对一般 rank 至少为 2 的 case，可以压缩为：

$$
[\text{batch}_L,\ldots,M,K]\ @\ [\text{batch}_R,\ldots,K,N]
\longrightarrow
[\operatorname{broadcast}(\text{batch}_L,\text{batch}_R),\ldots,M,N]
$$

公式不是要求你死背。它只是前面八步的压缩表达。

## 13. elementwise、dot 与 matmul 的职责

```python
u = np.array([1.0, 2.0, 3.0])
v = np.array([4.0, 5.0, 6.0])

elementwise = u * v
dot_value = np.dot(u, v)
matmul_value = u @ v
```

结果：

```text
elementwise.shape == (3,)
dot_value == 32.0
matmul_value == 32.0
```

区别：

| operation | 当前使用边界 |
|---|---|
| `*` | elementwise multiply，可使用 ordinary broadcasting |
| `np.dot(u,v)` | T3 只用于两个 1-D vectors 的 dot product |
| `A @ B` / `np.matmul(A,B)` | matrix 或 batch matrix multiplication |

`np.dot` 也定义了高维行为，但它与 N-D `matmul` 的 batch 规则不同。为避免一个符号承载多套高维语义，本路线的高维 matrix computation 统一优先使用 `@`。

## 14. transpose：N-D `.T` 会反转全部 axes

对 2-D array：

```text
x.shape   == (M,K)
x.T.shape == (K,M)
```

对 N-D array，`.T` 等价于不传 axes 的 `np.transpose(x)`，会反转全部 axes：

```text
x.shape   == (B,M,K)
x.T.shape == (K,M,B)
```

若目标是保留 batch axes，只交换每个 matrix 的最后两轴：

```python
matrix_transposed = np.swapaxes(x, -1, -2)
```

```text
(B,M,K) -> (B,K,M)
```

`axis=-1` 表示最后一个 axis，`axis=-2` 表示倒数第二个 axis。这个边界以后直接用于 Attention 中的 $K^T$。

官方查证，可选：[`numpy.transpose`](https://numpy.org/doc/stable/reference/generated/numpy.transpose.html) 与 [`numpy.swapaxes`](https://numpy.org/doc/stable/reference/generated/numpy.swapaxes.html)。

## 15. norm：把已有数学映射到 axis API

对一个 vector：

```python
vector = np.array([3.0, -4.0])

l1 = np.linalg.vector_norm(vector, ord=1)
l2 = np.linalg.vector_norm(vector, ord=2)
```

$$
\lVert(3,-4)\rVert_1=7,\qquad
\lVert(3,-4)\rVert_2=5
$$

对一批 vectors：

```python
vectors = np.array([
    [3.0, -4.0],
    [5.0, 12.0],
])

per_vector_l2 = np.linalg.vector_norm(
    vectors,
    ord=2,
    axis=-1,
)
```

`axis=-1` 表示每一行沿最后一个 axis 独立求 norm，结果 shape 是 `(2,)`，values 是 `[5.0, 13.0]`。

官方查证，可选：[`numpy.linalg.vector_norm`](https://numpy.org/doc/stable/reference/generated/numpy.linalg.vector_norm.html)。

## 17. 为什么 model computation 大量使用 matmul

今天只建立第一层连接：

```text
learned parameters 可以组织成 matrices
-> 同一 transformation 作用于许多 vectors
-> 大量 dot products 可以组成 matrix multiplication
-> batch matmul 把重复 computation 交给 numerical library
```

一个 linear projection：

$$
\begin{aligned}
\operatorname{shape}(X)&=[B,T,D_{\mathrm{in}}] \\
\operatorname{shape}(W)&=[D_{\mathrm{in}},D_{\mathrm{out}}] \\
Y&=XW \\
\operatorname{shape}(Y)&=[B,T,D_{\mathrm{out}}]
\end{aligned}
$$

按今天的规则：

```text
X batch = [B]
X core  = [T,D_in]
W batch = []
W core  = [D_in,D_out]
inner D_in match
W 的空 batch shape 可用于每个 B
result = [B,T,D_out]
```

这里为了直接右乘，使用 `W:[D_in,D_out]`。有些 framework 把 parameter 存成 `[D_out,D_in]`，forward 中会写 `X @ W.T`。读真实 code 时必须看 parameter layout，不能只凭变量名猜。

再看 Attention 以后会出现的 shape：

$$
\begin{aligned}
\operatorname{shape}(Q)&=[B,H,T,D] \\
\operatorname{shape}(K^T)&=[B,H,D,T] \\
\operatorname{shape}(QK^T)&=[B,H,T,T]
\end{aligned}
$$

今天只解释 shape：

```text
batch [B,H] 保留
inner D 被 reduction
两个 T 成为 output matrix dimensions
```

Q/K 怎样产生、scale、mask 与 softmax 留到 T16。能推 shape 不等于已经学完 Attention。

## 20. T3 压缩记忆

二维：

$$
[M,K]\ @\ [K,N]\longrightarrow[M,N]
$$

N-D：

$$
[\text{batch}_L,\ldots,M,K]\ @\ [\text{batch}_R,\ldots,K,N]
\longrightarrow
[\operatorname{broadcast}(\text{batch}_L,\text{batch}_R),\ldots,M,N]
$$

普通 broadcasting 从最右 axis 对齐：sizes 相等、其中一个为 $1$、或一方缺失时才 compatible。

N-D `.T` 反转全部 axes；只转置每个 batch matrix 时交换最后两个 axes。

先 prediction，再运行。2-D reference 负责 values 的透明 correctness oracle，NumPy result 负责验证 library semantics。
