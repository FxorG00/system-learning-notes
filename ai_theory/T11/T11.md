# Part 1：Round1，走通一次自动求导

## 0. 先看 `loss.backward()` 的输入与结果

先把一条能手算的链写开：

```python
import torch

x = torch.tensor(3.0)
w = torch.tensor(2.0, requires_grad=True)
b = torch.tensor(-1.0, requires_grad=True)

product = w * x
z = product + b
error = z - 4.0
loss = error ** 2
```

Forward（前向计算）得到：

```text
product = 6
z       = 5
error   = 1
loss    = 1
```

现在调用：

```python
print("before:", w.grad, b.grad)

backward_result = loss.backward()

print("backward return:", backward_result)
print("after:", w.grad, b.grad)
print("parameter values:", w.item(), b.item())
```

代表性输出：

```text
before: None None
backward return: None
after: tensor(6.) tensor(2.)
parameter values: 2.0 -1.0
```

这次调用只做了求导：

```text
调用对象：loss
方法返回：None
梯度结果：w.grad = 6，b.grad = 2
参数数值：w 和 b 都没有改变
```

所以最小用法是：

```text
forward 得到 scalar loss
-> loss.backward()
-> 从 w.grad、b.grad 读取结果
```

## 1. `backward()` 怎样算出 6 和 2

反向传播从 `loss` 开始。

`loss` 是 scalar（标量），它对自己的导数是：

$$
\frac{\partial L}{\partial L}=1
$$

这个 `1` 是反向计算的起点。

### 1.1 平方

Forward 做的是：

$$
L=error^2
$$

本例 `error=1`：

$$
\frac{\partial L}{\partial error}
=
1\times 2error
=2
$$

PyTorch 中负责这一步反向规则的节点叫 `PowBackward0`。

### 1.2 减法

Forward 做的是：

$$
error=z-4
$$

减法对 `z` 的局部导数是 `1`：

$$
\frac{\partial L}{\partial z}
=
2\times 1
=2
$$

负责这一步的节点叫 `SubBackward0`。

### 1.3 加法

Forward 做的是：

$$
z=product+b
$$

加法对两侧的局部导数都是 `1`。上游梯度 `2` 分成两路：

$$
\frac{\partial L}{\partial product}=2,
\qquad
\frac{\partial L}{\partial b}=2
$$

负责这一步的节点叫 `AddBackward0`。

### 1.4 乘法

Forward 做的是：

$$
product=wx
$$

乘法对 `w` 的局部导数是 `x`。本例 `x=3`：

$$
\frac{\partial L}{\partial w}
=
\frac{\partial L}{\partial product}
\frac{\partial product}{\partial w}
=
2\times 3
=6
$$

负责这一步的节点叫 `MulBackward0`。

整条反向路径就是：

```text
loss 端从 1 开始
-> 平方：传给 error 的梯度是 2
-> 减法：传给 z 的梯度是 2
-> 加法：分别传给 product 和 b，b 得到 2
-> 乘法：2 * x，w 得到 6
```

**每一步都接住上游梯度，乘上当前运算的局部导数，再继续往前传。**

## 2. PyTorch 为什么知道该走哪条路

Forward 不只算出数值。

当运算涉及需要梯度的 Tensor 时，PyTorch 还会记录：

```text
这个结果由哪一步运算产生
这一步依赖哪些前驱
backward 到这里时使用哪条局部求导规则
```

这些关系连起来，就是 computation graph（计算图）。

![本例从 loss 回到 w.grad 与 b.grad 的反向路径](images/computation_graph.svg)

图里的分叉来自加法：

```text
z = product + b
```

所以 `AddBackward0` 会把梯度送往 `product` 和 `b` 两侧。`product` 继续经过乘法回到 `w`，最终结果分别进入 `w.grad`、`b.grad`。

## 3. 用三个属性观察这条关系

### 3.1 `requires_grad`：是否需要追踪求导关系

```python
print(w.requires_grad)        # True
print(x.requires_grad)        # False
print(product.requires_grad)  # True
print(loss.requires_grad)     # True
```

`w` 需要梯度，所以由它参与产生的后续结果会保留求导关系。

`x` 不要求得到自己的梯度。不过反向计算 `w.grad` 时仍要读取 `x=3`。

### 3.2 `grad_fn`：最后是哪一步运算产生了我

`grad_fn` 是 Tensor 的一个属性：

```text
grad = gradient，梯度
fn   = function，函数
```

先看打印结果：

```python
print(product.grad_fn)
print(z.grad_fn)
print(error.grad_fn)
print(loss.grad_fn)
print(w.grad_fn)
```

代表性输出：

```text
<MulBackward0 object at ...>
<AddBackward0 object at ...>
<SubBackward0 object at ...>
<PowBackward0 object at ...>
None
```

例如：

```python
z = product + b
```

产生 `z` 的最后一步是加法，所以：

```text
z.grad_fn -> AddBackward0
```

这个节点告诉 `backward()`：走到 `z` 时，按加法的局部规则继续传梯度。

`w` 由用户直接创建，不是某一步运算的结果，所以 `w.grad_fn` 是 `None`。

### 3.3 Leaf Tensor：最终梯度默认保存在哪里

`w`、`b` 由用户直接创建，是 leaf Tensor（叶子张量）。

`product`、`z`、`error`、`loss` 由运算产生，是 non-leaf Tensor（非叶子张量）。

```python
print(w.is_leaf)     # True
print(z.is_leaf)     # False
print(loss.is_leaf)  # False
```

默认情况下，`backward()` 把结果保存到需要梯度的 leaf 的 `.grad`：

```text
w.grad = 6
b.grad = 2
```

把两个名字分开：

```text
.grad_fn：当前结果怎样回到前驱
.grad：已经算出的 leaf 梯度数值
```

## 4. Round1：三条路径检查同一个梯度

文件：`autograd_inspect.py`

R1 用同一点比较：

```text

```

固定输入：

```python
x = torch.tensor(-2.0, dtype=torch.float64)
w = torch.tensor(1.5, dtype=torch.float64, requires_grad=True)
b = torch.tensor(0.5, dtype=torch.float64, requires_grad=True)

z = w * x + b
loss = (z - 1.0) ** 2
```

手算结果：

$$
\frac{\partial L}{\partial w}=14,
\qquad
\frac{\partial L}{\partial b}=-7
$$

有限差分继续复用 T4 已通过的检查器。目标函数是：

```python
def fixed_loss(parameters):
    w_value, b_value = parameters
    return float((w_value * (-2.0) + b_value - 1.0) ** 2)
```

运行前先预测：

```text
w、z、loss 的 requires_grad / is_leaf / grad_fn
第一次 backward 后 w.grad、b.grad
参数不变且不清理 .grad，再重新 forward/backward 后的结果
```

R1 证明三件事：

1. 手算、有限差分、autograd 得到同一组梯度。
2. `backward()` 把结果写进 leaf 的 `.grad`。
3. 不清理 `.grad`，第二次新计算的梯度会加到旧值上。

三路单次梯度使用 `rtol=1e-5, atol=1e-7`。全部通过后打印：

# Part 2：Round2，分开两种生命周期

## 5. `.grad` 默认累加

R1 的单次梯度是：

```text
w.grad = 14
b.grad = -7
```

参数不变，再做一次新的 forward/backward：

```text
w.grad = 28
b.grad = -14
```

两次单次梯度相同。第二份结果被加到已有 `.grad` 上。

这叫 gradient accumulation（梯度累积）。

如果下一次只需要一份新梯度，先清理：

```python
w.grad = None
b.grad = None
```

重新 forward/backward 后，结果恢复为 `14` 和 `-7`。

T12 使用 optimizer（优化器）时，会统一清理多个参数的梯度。本课先看清 `.grad` 自己的行为。

## 6. 旧 `.grad` 还在，不代表旧图还能再用

新建一组对象：

```python
old_x = torch.tensor(-2.0, dtype=torch.float64)
old_w = torch.tensor(1.5, dtype=torch.float64, requires_grad=True)
old_b = torch.tensor(0.5, dtype=torch.float64, requires_grad=True)

old_z = old_w * old_x + old_b
old_loss = (old_z - 1.0) ** 2

old_loss.backward()
old_loss.backward()  # 不重新 forward，故意复用同一个 old_loss
```

第二次调用会抛出 `RuntimeError`。代表性开头是：

```text
Trying to backward through the graph a second time ...
```

第一次 backward 后发生了两件不同的事：

```text
old_w.grad / old_b.grad
-> 结果仍保存在 leaf 上

旧图为反向计算保存的中间状态
-> 默认按一次反传使用，之后释放
```

所以：

```text
.grad 的生命周期
!=
旧 loss 再次 backward 所需状态的生命周期
```

正常训练会根据当前参数重新 forward，得到新的 loss 和新图。`retain_graph=True` 只用于确实需要复用同一张图的场景，本课不用它解决普通训练流程。

> 选看：non-leaf 的梯度参与计算，但默认不留在自己的 `.grad`。调试时可在 backward 前调用 `z.retain_grad()`；它不改变求导结果，只额外保存 `z.grad`。这不是 R2 通过条件。

# Part 3：Round3，把求导请求说完整

## 8. 向量输出：先说最终关心哪个标量

假设：

```python
x = torch.tensor([1.0, 2.0, 3.0], requires_grad=True)
y = x ** 2
```

`y` 有三个数。直接调用：

```python
y.backward()
```

会失败，因为 PyTorch 不知道三个输出怎样组成你最终关心的一个目标。

假设真正关心：

$$
F=y_0+0.5y_1-y_2
$$

权重向量是：

```python
v = torch.tensor([1.0, 0.5, -1.0])
```

两种写法表达同一个问题。下面分别新建对象，避免第一次 backward 消耗的图影响第二次：

> 要么，最后是一个 scalar 调用 backward
>
> 要么，是 Tensor 调用 backward 并且我们提供每个输出的权重
>
> 也就是，
> $$
> \frac{\partial F}{\partial y_i}=v_i,
> $$

```python
# 写法一：先显式组成 scalar
x1 = torch.tensor([1.0, 2.0, 3.0], requires_grad=True)
y1 = x1 ** 2
F = y1[0] + 0.5 * y1[1] - y1[2]
F.backward()
print(x1.grad)

# 写法二：直接提供每个输出的上游权重
x2 = torch.tensor([1.0, 2.0, 3.0], requires_grad=True)
y2 = x2 ** 2
y2.backward(v)
print(x2.grad)
```

两种写法都得到：

```text
x.grad = [2, 2, -6]
```

这个“用向量加权各输出，再把结果传回输入”的计算叫 VJP（vector-Jacobian product，向量-雅可比乘积）。

先理解加权标量目标，再记 VJP 这个名字。

## 9. 哪些计算需要留下求导关系

三种常见动作解决三个不同场景：

| 场景 | 动作 |
|---|---|
| 接下来一小段计算只要数值 | `with torch.no_grad():` |
| 已有结果要交给不需要旧图的后续代码 | `result.detach()` |
| 整个请求都是纯预测 | `with torch.inference_mode():` |

用同一个输入观察：

```python
source = torch.tensor(2.0, requires_grad=True)

tracked = source * 3.0

with torch.no_grad():
    untracked = source * 3.0

detached = tracked.detach()

with torch.inference_mode():
    inference_value = source * 3.0
```

四个结果的数值都是 `6`。

区别在求导关系：

```text
tracked.requires_grad         = True
untracked.requires_grad       = False
detached.requires_grad        = False
inference_value.requires_grad = False
```

`no_grad` 管接下来这段运算。`detach` 管一个已经算好的结果。`inference_mode` 管完整的纯预测边界。

T10 已经学过：

```python
model.eval()
with torch.inference_mode():
    output = model(input)
```

`eval()` 选择模型的评估行为，`inference_mode()` 关闭本次预测不需要的求导记录。两者各管一件事。

## 10. Backward 需要的旧值不能被随意改掉

平方的导数需要 forward 时的输入值：

$$
\frac{d(x^2)}{dx}=2x
$$

先算平方，再在 backward 前原地修改同一个 Tensor：

```python
saved = torch.tensor([2.0], requires_grad=True)
square_loss = (saved ** 2).sum()

with torch.no_grad():
    saved.add_(1.0)

square_loss.backward()
```

`add_` 末尾的下划线表示 in-place（原地）修改。`saved` 从 `2` 变成 `3`。

但 `square_loss` 的反向计算需要原来的 `2`。PyTorch 检测到这个值在 forward 后被改过，因此抛出 `RuntimeError`。

本课结论是：

```text
forward 为 backward 保存了旧值
-> backward 结束前，这些值不能被随意原地修改
```

这不表示所有 in-place 操作都错误。当前先保证求导正确；性能阶段再用 profiler 判断某项原地优化是否值得。

## 12. 为什么训练内存比参数本身更大

训练时同时存在：

```text
参数值
参数的 .grad
backward 需要的中间值
求导关系与临时工作空间
```

T12 加入 optimizer 后，还可能有优化器状态。

纯推理只要 forward 结果，不需要为本次请求保留反向关系与训练中间值。因此推理服务会明确使用评估行为和推理执行边界。

若 serving path 意外开启梯度跟踪，输出数值可能仍正确，但内存与延迟会多出不需要的成本。

模型更大以后，还会遇到 activation checkpointing（激活检查点）：少保存一部分中间值，backward 时重新计算，用计算换内存。本课只建立这条连接，不实现它。
