# Part 1：模型的分数怎样进入你的 T5 采样器

## 0. 今天要修复什么

你在 T5 已经写出 `sample_categorical(probabilities, sample_count, rng)`：传入 `[0.2, 0.3, 0.5]`，返回一串 `0/1/2` 类别下标；再统计它们的频率。你也修正了候选数量，现在它由概率向量的长度决定。

**T6 解决这一步之前的问题：模型给出的是分数，怎样把分数变成采样器能使用的概率？** 原来的采样器已经通过，不需要重写。

### 0.1 先让三个分数有出处

假设我们要判断一张图片属于哪一类，事先规定类别下标：

| 下标 | 类别 | 模型对这张图片给出的分数 |
|---|---|---|
| `0` | cat（猫） | `2.0` |
| `1` | dog（狗） | `4.0` |
| `2` | bird（鸟） | `1.0` |

一张图片是一个 **input example（输入数据样例）**。模型处理它后，对每个 class（类别）各算一个 score（分数），合起来就是：

$$
\mathbf z=[2.0,4.0,1.0]
$$

这种用于后续概率转换的原始分数叫 **logits（尚未归一化的分类分数）**。每一项绑定一个类别；当前模型最倾向狗，因为狗的分数最高。

**分数表达相对倾向，概率表达一组结果各自的权重。** Logit 可以是负数、可以大于 `1`，所有项的和也没有固定要求。这里的 `4.0` 还不能直接传给 T5 当作狗的概率。

### 0.2 分数从哪里算出来：接回你学过的线性模型

你在 logistic regression（逻辑回归）里已经见过：

$$
z=\mathbf w^{\mathsf T}\mathbf x+b
$$

模型先对输入特征做加权求和，再加偏置，得到一个实数。多分类的线性模型沿用这个动作，只是**每个类别各有一组权重和一个偏置**：

$$
z_c=\mathbf x^{\mathsf T}\mathbf w_c+b_c,
\qquad c=0,\ldots,C-1
$$

$C$ 是类别数，$\mathbf w_c$ 是第 $c$ 类的权重。把各类权重并排放成矩阵 $W$，得到：

$$
\mathbf z=\mathbf x^{\mathsf T}W+\mathbf b
$$

拿两个特征做一个可以手算的示例。暂时给定参数，不在 T6 训练它们：

$$
\mathbf x=\begin{bmatrix}1\\2\end{bmatrix},
\qquad
W=\begin{bmatrix}1&2&0\\0.5&1&0.5\end{bmatrix},
\qquad
\mathbf b=[0,0,0]
$$

**$W$ 的三列依次属于猫、狗、鸟；同一个输入分别与三列做点积。**

$$
z_0=1\times1+2\times0.5=2
$$

$$
z_1=1\times2+2\times1=4
$$

$$
z_2=1\times0+2\times0.5=1
$$

所以 `[2,4,1]` 有明确来源：它是这次模型计算的三个输出。实际图片通常会有更多特征，或者先经过神经网络；这里用两项特征，只为看清分数的产生过程。

用你在 T2/T3 已经会的 NumPy 写，就是：

```python
import numpy as np

x = np.array([1.0, 2.0])
weights = np.array([[1.0, 2.0, 0.0], [0.5, 1.0, 0.5]])
bias = np.array([0.0, 0.0, 0.0])
logits = x @ weights + bias
print(logits)  # [2. 4. 1.]
```

一条输入有 $D$ 个特征、模型要区分 $C$ 个类别，对应的 shape 是：

```text
x [D] @ W [D,C] + b [C]
-> logits [C]

X [B,D] @ W [D,C] + b [C]
-> logits [B,C]
```

第二种把 $B$ 条输入放在同一个 batch（批次）里计算。**输出的一整行属于一条输入；一行中的每一项属于一个类别。** 偏置 `[C]` 会通过 broadcasting 加到每行上。

### 0.3 接上 T5，并区分两种 sample

在机器学习资料里，一张图片、一行训练数据也常叫 input sample。你在 T5 的 sampling（随机采样）却是另一个动作：给定 `[0.2,0.3,0.5]`，随机抽到某个类别下标。

本篇用 **input example 表示送进模型的输入，用 random draw（一次随机抽取结果）表示采样器的输出**，把两者分开。

今天完整的对象链是：

```text
input example x：一张图片的特征
        |
        v
model：用当前参数计算
        |
        v
logits [C]：[2.0, 4.0, 1.0]
        |
        v
softmax：把分数转换成概率
        |
        v
probabilities [C]：约 [0.114, 0.844, 0.042]
        |
        +--> argmax：选择最大项，得到类别 1
        |
        +--> 你的 T5 sampler：随机抽取，可能得到类别 1
```

`argmax` 是取最大项的下标；`sampler` 是你已经写好的采样器。下节会讲概率怎么产生，以及为什么第二条路仍可能抽到 `0` 或 `2`。

如果要评价模型，还有另一条链：

```text
这张图片的 logits + 数据提供的 true label（真实类别标签）
-> cross entropy（交叉熵）
-> scalar loss（一个标量误差值）
```

**真实标签来自数据中的答案；随机抽出的类别来自模型的概率分布。** 即使采样器抽到狗，图片的真实标签也不会因此变成狗。

### 0.4 今天带着四个问题往下读

1. 模型产生了分数，为什么你的 T5 接口还不能直接使用它？
2. 怎样把任意实数分数转成非负、总和为 `1`、保持类别排序的概率？
3. 数学公式已经成立，为什么计算机仍可能算出无穷或无效结果？
4. 已知真实标签后，怎样稳定地算出模型给这份答案的 loss？

## 1. Softmax 为什么自然出现

### 1.1 先有需求：采样器要的是合法概率

你的 `sample_categorical` 会检查每项非负、全部有限，而且总和约等于 `1`。数学上，一组 categorical probabilities（各离散类别的概率）必须满足：

$$
p_i\ge0,
\qquad
\sum_{i=0}^{C-1}p_i=1
$$

对于 `[2,4,1]`，直接除以总和 `7`，确实能得到一组合法概率。但模型也可能输出 `[-2,4,1]`；除以总和 `3` 后，第一项为负。这个办法不能处理任意实数分数。

于是需要一个转换：**接收 $C$ 个任意实数，输出 $C$ 个合法概率，同时让原先分数较高的类别仍有较高概率。** Softmax 是机器学习中常用的一种平滑、可微的转换，下面从它的两个动作看起。

### 1.2 第一步：把每个分数变成正权重

指数函数满足 $e^z>0$，对正数、零、负数都成立。先对每个分数取指数：

$$
u_i=e^{z_i}
$$

而且指数函数单调递增：若 $z_i>z_j$，就有 $e^{z_i}>e^{z_j}$。所以这一步同时做到：

```text
任意实数 -> 正数
分数大小关系 -> 正权重的大小关系
```

现在得到的是 positive weights（正权重），还没有保证总和为 `1`。

### 1.3 第二步：把权重的总量分配成 1

**每项除以所有权重之和，得到它占总量的比例。** 这个动作叫 normalization（归一化）：
$$
p_i
=
\frac{e^{z_i}}
{\sum_{j=0}^{C-1}e^{z_j}}
$$

分子为正、分母为正，所以每项为正；所有分子相加正好等于分母，所以概率之和为 `1`：

$$
p_i>0,
\qquad
\sum_{i=0}^{C-1}p_i=1
$$

这两步合起来就是 **softmax（把分类分数指数化后归一化的概率映射）**。

用一组能精确算完的数字看这两个动作，$\log$ 在本篇表示自然对数：

$$
[0,0,\log 2]
\longrightarrow [1,1,2]
\longrightarrow [0.25,0.25,0.5]
$$

第一箭头是取指数，第二箭头是除以总和 `4`。最后得到的向量，正是 T5 采样器接受的那种对象。

再回到猫、狗、鸟的分数 $[2,4,1]$，概率约为：

$$
\mathbf p=[0.114195,0.843795,0.042010]
$$

狗仍排名第一，而三项现在共同构成一个概率分布。**这是模型给出的预测分布；它是否符合真实数据，要靠标签和评价来判断。**

这里的 $C$ 也接上你现在的 `range(len(probabilities))`：有多少个类别，就有多少项。三类只是示例，不是函数的固定限制。

### 1.4 概率算完以后，才决定怎样使用它

对上述概率使用 `argmax`，确定地得到下标 `1`。使用 T5 的采样器，一次抽到 `1` 的概率约为 `0.844`，但也可能抽到 `0` 或 `2`。

```text
logits
  |
  v
softmax
  |
  v
probabilities
  +--> argmax -> 确定性预测
  +--> categorical sampling -> 随机抽取的类别
```

**Softmax 的职责到概率向量为止；选择最大项和随机抽取是后续两种用法。** 由于它在数学上保留排序，若只要最大分数的类别，也可以直接对 logits 做 `argmax`，省去概率计算。

### 1.5 选看：为什么常用指数，而不是随便一个正函数

非负、和为 `1`、保序这几个要求，并不能唯一推出 softmax。选择指数还带来一个方便的性质：

$$
\frac{p_i}{p_j}=e^{z_i-z_j},
\qquad
\log\frac{p_i}{p_j}=z_i-z_j
$$

**两个类别的分数差，直接决定它们的概率比。** 例如某类比另一类高 $\log 2$，它的概率就是另一类的两倍；其他类别会影响各自的具体概率，但不会改变这两个类别之间的比值。

这也给下一节的数值问题埋下线索：我们关心的是分数之间的相对差距，而不是一定要计算一个特别巨大的指数。

本节可选查证：[《动手学深度学习》Softmax Regression](https://d2l.ai/chapter_linear-classification/softmax-regression.html) 的线性输出、softmax 与批量计算部分；正文已经给出本课需要的对象和公式。

## 2. 数学正确为什么不等于数值安全

现在对象已经站稳：模型交付 logits，softmax 交付概率，T5 接收概率。接下来检查，**直接照这个正确公式执行，浮点数能否装下中间结果**：

```python
def naive_softmax(logits: np.ndarray) -> np.ndarray:
    exponentials = np.exp(logits)
    return exponentials / np.sum(exponentials)
```

输入 `[1,2,3]` 时通常工作。现在才拿 `[1000,1001,1002]` 作为数值压力案例：它们仍是三个类别的分数，但直接取指数会 overflow（上溢，中间结果超过浮点类型能表示的范围）：

```text
np.exp(1000) -> inf
inf / inf      -> nan
```

`inf` 是 infinity（无穷表示）；`nan` 是 not-a-number（未定义数值结果）。问题出在 intermediate values（中间计算值）超出 dtype 范围。

另一端也可能 underflow（下溢）：极小正数被舍入成 `0`。若随后计算 `log(0)`，结果会变成 `-inf`。

数值程序必须同时关心：

```text
最终数学值
中间值是否能被当前 dtype 表示
等价表达在浮点运算下的误差
```

## 3. 找到稳定写法所需的不变量

给所有 logits 同时加一个 constant（常数）$c$：

$$
\frac{e^{z_i+c}}
{\sum_j e^{z_j+c}}
=
\frac{e^ce^{z_i}}
{e^c\sum_j e^{z_j}}
=
\frac{e^{z_i}}
{\sum_j e^{z_j}}
$$

因此：

$$
\operatorname{softmax}(\mathbf z)
=
\operatorname{softmax}(\mathbf z+c)
$$

这叫 translation invariance（整体平移不变性）。我们可以先把整组 logits 平移到更安全的范围，再取指数。

先停在这里。你已经知道：

```text
所有 logits 必须减同一个值
平移后 probabilities 不变
希望平移后的最大 exponent 不再溢出
```

## 4. Batch 情况先明确 axis

若 logits shape 是 `[B,C]`：

```text
B：这个批次的输入条数
C：每条输入的候选类别数
```

沿用 §0.2 的 `[B,D] -> [B,C]`：每一行是一条 input example 的类别分数。**每条输入都有自己的概率分布**，所以归一化必须沿 class axis（类别轴），即 `axis=-1`：

$$
\sum_{c=0}^{C-1}p_{b,c}=1
\quad
\text{for every }b
$$

若沿 batch axis（批次轴）归一化，会变成“同一类别在不同输入之间分配概率”。例如猫这一列总和为 `1`，并不能回答某一张图片属于猫、狗、鸟各有多少概率。Axis 决定我们正在建立哪一个分布。

## 5. 开工前只需要这些 API

```python
np.exp(values)
np.max(values, axis=-1, keepdims=True)
np.sum(values, axis=-1, keepdims=True)
np.log(values)
np.isfinite(values)
np.testing.assert_allclose(actual, expected, rtol=..., atol=...)
```

`keepdims=True` 保留 reduction axis（被聚合的轴）为长度 `1`，让 `[B,1]` 可以 broadcast 回 `[B,C]`。这里只解释 shape，不给稳定函数的完整组合。

# Part 2：Round1，独立找到稳定的概率计算路径

## 6. 程序用途与 contract

文件：`stable_softmax.py`

今天造的是一份 **naive vs stable numerical experiment（普通实现与稳定实现的数值对照实验）**。两个 functions 完成相同的数学任务，但 floating-point execution 不同：

```text
ordinary logits
├─ naive_softmax  -> probabilities
└─ stable_softmax -> probabilities
                    两者应接近

extreme logits
├─ naive_softmax  -> 预期出现 non-finite
└─ stable_softmax -> finite probabilities，sum 约等于 1
```

Round1 先只闭合这张对照图。闸门后再增加第二条程序链：

```text
logits + correct-class label
-> stable logits-space calculation
-> cross-entropy scalar loss
```

对象角色：

| 对象 | 角色 |
|---|---|
| `logits` | model 产生的原始类别分数；一条输入对应一组分数 |
| `naive_softmax` | logits -> probabilities 的数学 operation |
| `stable_softmax` | 同一数学 operation 的数值稳定实现 |
| `cross_entropy_from_logits` | 闸门后加入的 scalar loss function |

`naive_softmax` 与 `stable_softmax` 都不是 model，也不是 optimizer；它们只是同一 operation 的两种 floating-point implementation。Round1 的认知墙是怎样找到稳定等价写法，不是猜程序为什么同时需要两个 functions。

先看 caller 怎样比较两条路径：

```python
ordinary = np.array([1.0, 2.0, 3.0], dtype=np.float64)

naive = naive_softmax(ordinary)
stable = stable_softmax(ordinary)

np.testing.assert_allclose(naive, stable, rtol=1e-12, atol=1e-12)
```

现在再给 public signatures；稳定实现内部怎样组织 shift 仍由你独立完成：

```python
def naive_softmax(logits: np.ndarray, axis: int = -1) -> np.ndarray:
    ...


def stable_softmax(logits: np.ndarray, axis: int = -1) -> np.ndarray:
    ...
```

输入：

```text
floating ndarray
至少 1-D
目标 axis 长度 > 0
所有 logits finite
```

输出：

```text
shape 与 input 相同
所有 values finite 且非负
沿 axis 的 sums 约等于 1
不修改 caller input
```

你的 T5 已经证明了“概率 -> 随机抽取结果”这半条链。今天把注意力放在 **shape 不变、类别轴归一化、极端分数仍能给出有限结果**；先检查输出 probabilities，不必再跑百万次采样来验证 T5 的部分。下面固定 cases 用三类展示数值现象，不把函数限制为三类。

固定 cases：

```python
ordinary = np.array([1.0, 2.0, 3.0], dtype=np.float64)
extreme = np.array([1000.0, 1001.0, 1002.0], dtype=np.float64)
batch = np.array(
    [
        [1.0, 2.0, 3.0],
        [1000.0, 1001.0, 1002.0],
        [-1000.0, -1001.0, -1002.0],
    ],
    dtype=np.float64,
)
```

最低 evidence：

```text
ordinary 上 naive 与 stable 接近
extreme 上主动捕获 naive 的 non-finite
stable extreme 全 finite 且 sum == 1
batch 每行独立归一化
stable_softmax 不修改 input
整体加 500 后 probabilities 不变
```

Naive failure 是预期观察：

```python
with np.errstate(over="ignore", invalid="ignore"):
    naive_result = naive_softmax(extreme)
```

## 6.0 解释几个 evidence

这三项分别检查：**每组概率算对了、原数据没被改、分数整体平移后结果仍一致。**

**1. batch 每行独立归一化**
你 T6 的 `batch` 有三行，每行代表一组类别分数。应该**每行各自得到一份概率分布**：

```text
第 1 行概率之和 ≈ 1
第 2 行概率之和 ≈ 1
第 3 行概率之和 ≈ 1
```

而且，把某一行单独交给 softmax，应该与批量计算中那一行的结果一致。

**2. stable_softmax 不修改 input**
传进去的是原始分数，函数返回概率，但**调用后原来的 batch 应该还是那些分数**。调用前用 `.copy()` 保存独立副本，调用后比较。

**3. 整体加 500 后 probabilities 不变**
例如：

```text
[1, 2, 3]
[501, 502, 503]
```

所有类别一起加了相同的数，彼此的分数差没变，因此 softmax 概率也应相同。浮点计算允许微小误差，所以用 `np.allclose` 检查“足够接近”，而不是要求逐位完全相等。

用你已有的 `batch`，可以这样观察，不涉及稳定算法的实现：

```python
before = batch.copy()
p = stable_softmax(batch, axis=-1)

# 先检查函数有没有修改原数据。
print("输入保持不变：", np.array_equal(batch, before))

# 三行各自归一化，应接近 [1, 1, 1]。
print("各行概率之和：", p.sum(axis=-1))

# 批量中的每行，应与单独计算该行一致。
for i in range(len(before)):
    single = stable_softmax(before[i].copy())
    print("第", i, "行与单独计算一致：", np.allclose(p[i], single))

# 每个分数都加 500，再比较概率。
shifted = stable_softmax(before + 500, axis=-1)
print("加 500 后概率一致：",
      np.allclose(p, shifted, rtol=1e-12, atol=1e-12))
```

预期：各行之和接近 `[1, 1, 1]`，其余检查全部打印 `True`。

`np.array_equal` 检查元素完全相等；`np.allclose` 检查浮点结果在容差内接近。

## 6.1 softmax 对 logits 的哪一个 axis 做？为啥是这个

> 沿 class 所在的 axis 去做。把每个类别的分数转化为概率。

**Softmax 应沿“类别所在的轴”计算，不是看有几个维度就随便选一个轴。** 每一组类别分数，要变成自己的一份概率分布。

假设最后一维保存类别：

| logits 的 shape | 含义 | 使用哪个 axis |
|---|---|---|
| `(3,)` | 一组分数，3 个类别 | `0`，也就是 `-1` |
| `(2, 3)` | 两条输入，每条有 3 个类别分数 | `1`，也就是 `-1` |
| `(2, 4, 3)` | 共 8 组分数，每组有 3 个类别 | `2`，也就是 `-1` |

例如：


## 7. 你选择的减 maximum，为什么同时保留概率并控制指数范围

你的实现现在是：

```python
logits_copy = logits.copy()
logits_copy = logits_copy - np.max(logits_copy, axis=axis, keepdims=True)
exponentials = np.exp(logits_copy)
return exponentials / np.sum(exponentials, axis=axis, keepdims=True)
```

这里的 `logits_copy` 第一次指向原 scores 的副本；执行第二行后，它指向减去 maximum 得到的新数组。你没有改变 caller 的输入，独立检查也验证了这一点。

你在注释里已经写出“整体加一个常数不影响概率”。对一组类别分数，这个理由是：

$$
\frac{e^{z_i+c}}{\sum_j e^{z_j+c}}
=
\frac{e^c e^{z_i}}{e^c\sum_j e^{z_j}}
=
\frac{e^{z_i}}{\sum_j e^{z_j}}
$$

**同一组类别一起平移，分子和分母增加的同一个因子会约掉。** 每组可以选择自己的常数，但组内所有类别必须一起移动。你的 `max` 和 `sum` 现在使用同一个 `axis`，正好守住这个关系。

为什么偏偏减 maximum？设 $m=\max_i z_i$，则 $z_i-m\le0$。最大的指数值成为 $e^0=1$，其余指数值在数学上位于 $(0,1]$。

```text
你已经测过的 [1000,1001,1002]
-> 同组减去 1002
-> [-2,-1,0]
-> exp 约为 [0.1353,0.3679,1.0]
-> 归一化约为 [0.0900,0.2447,0.6652]
```

原先会使 exp 上溢的巨大数，变成了可以表示的指数值，而数学上的 probabilities 没变。浮点数仍有精度限制，很小的指数项可能下溢为 `0`；这正是 §9 要接着处理的新问题。

### 7.1 把你修好的两个 keepdims 放回同一条 shape 链

你注释中的 `[A,B,C]`、`[A,B,1]` 和分母下标 `sum[i,j,0]` 现在与实际代码一致。若 `axis=-1`：

```text
logits [A,B,C]
-> max(..., keepdims=True) [A,B,1]
-> subtract，广播回 [A,B,C]
-> exp [A,B,C]
-> sum(..., keepdims=True) [A,B,1]
-> divide，输出仍为 [A,B,C]
```

长度为 `1` 的轴保留下来，maximum 和 denominator 才能对准原数组的每组类别。`keepdims` 控制的是 reduction 后的形状；`axis` 控制的是哪些元素组成同一组，两者负责不同的事情。

同样一个 `(2,3)` 数组，若 caller 选择 `axis=0`，组就变成每一列里的两个元素，max/sum 都应得到 `(1,3)`。**逐行计算只是 `[B,C] + axis=-1` 的具体场景；通用接口的规则是沿 caller 选择的类别轴计算。**

你原来的固定 `3x3` batch 各行平移后的分母恰好相同，因而曾经掩盖错误。复检已经用非方阵和不同分母拆开这个巧合；这是本次修正的证据，不是让你追加一批重复练习。

### 7.2 你的 copy 是正确的保护，但要区分两种修改

你的 `.copy()` 保留即可。对于当前 numeric ndarray，它创建独立的数据存储；之后如何计算都不会通过这份副本直接写回 caller。

这里顺手把注释说得更精确：

- `values -= maximum`：原地改 `values` 指向的数据，若它与 caller 共用存储，会影响 caller。
- `values = values - maximum`：先计算新数组，再让局部名字 `values` 指向它，原输入不会被这次减法改动。

所以你的做法正确，但“函数中计算一定需要 copy”并不成立。你这版既复制、又使用非原地减法，属于保守的保护方式；今天不用为省一次 copy 去重构已通过的函数。

## 8. 你的 probabilities 现在可以给真实答案计分

你已经完成的是 `scores -> probabilities`。下一步换一个消费者：**用数据给出的真实标签，从概率向量中取出正确类别的概率，再衡量预测有多差。**

回到前面的猫/狗/鸟例子，模型给出 `[2,4,1]`。假设图片实际是一只鸟，真实标签 $y=2$；你现在的 `stable_softmax` 会给鸟约 `0.042010` 的概率。

标签固定为 `2`，直接取第 `2` 项 $p_y$。这条 loss 路径不需要调用 T5 sampler：真实答案由数据提供，不由模型随机抽出来。

我们想要的计分规则是：

```text
给真实答案的概率越接近 1 -> loss 越接近 0
给真实答案的概率越接近 0 -> loss 越大
```

负对数刚好满足这个方向。把它用在真实类别的概率上，得到 negative log-likelihood（负对数似然）：

$$
L=-\log p_y
$$

这张鸟图的 loss 约为 `3.169846`。如果同样的预测对应真实的狗图，$y=1$，loss 约为 `0.169846`。**同一组预测，配上不同的真实标签，分数可以完全不同。**

把标签 `2` 写成 one-hot target（正确类别为 `1`、其余类别为 `0` 的目标向量）$\mathbf q=[0,0,1]$，cross entropy（交叉熵）写成：

$$
L=-\sum_{c=0}^{C-1}q_c\log p_c
$$

只有真实类别的 $q_y=1$，于是本课的交叉熵就是 $-\log p_y$。$y$ 是类别下标，$\mathbf q$ 是目标向量；其他类别的分数仍会通过 softmax 的分母影响 $p_y$。

今天用类别下标作为函数输入，不需要额外构造 one-hot 数组。

## 9. 你的 softmax 已经稳定，为什么直接 log 仍会失败

先用已经通过的函数看一个更偏的分布：

```python
logits = np.array([0.0, -1000.0], dtype=np.float64)
probabilities = stable_softmax(logits)
print(probabilities)  # [1. 0.]
```

减 maximum 已经避免了 exp 上溢。但 `exp(-1000)` 太小，float64 会把它舍入成 `0`。若真实标签是 `1`，接着计算 `-np.log(probabilities[1])` 就得到 `inf`。

**这不是你的 R1 又写错了，而是先落到 probability、再取 log，会丢掉极小概率的信息。** 我们需要从 logits 直接算 loss，绕过这一步。

### 9.1 从你已经使用的分母推到 log-sum-exp

对真实类别 $y$：

$$
p_y=\frac{e^{z_y}}{\sum_j e^{z_j}}
$$

取负对数并拆开分子、分母：

$$
-\log p_y
=
\log\sum_j e^{z_j}-z_y
$$

反复出现的“指数求和再取对数”，叫 log-sum-exp（指数和的对数，简称 LSE）：

$$
\operatorname{LSE}(\mathbf z)=\log\sum_j e^{z_j}
$$

你的 R1 已经知道怎样让指数安全：减 $m=\max_j z_j$。把这个动作带过来：

$$
\operatorname{LSE}(\mathbf z)
=
m+\log\sum_j e^{z_j-m}
$$

它和你的 softmax 共用同样的平移思路，只是最后要把 $m$ 加回来，因为 LSE 本身会随整体平移一起变化。**softmax 对平移不变；LSE 对整体加 $c$，结果也加 $c$。**

### 9.1.0 ndarray 怎么压缩掉最后一维，并且最后一维 size=1

用 **`np.squeeze`，指定去掉最后一维**：

```python
x = np.array([[1], [2], [3]])  # shape: (3, 1)

y = np.squeeze(x, axis=-1)
print(y.shape)                # (3,)
print(y)                      # [1 2 3]
```

**`axis=-1` 指定最后一维，它的大小必须为 `1`，否则会报 `ValueError`。**

不要省略 `axis`：`np.squeeze(x)` 会去掉**所有大小为 1 的维度**，可能把你想保留的 batch 维也去掉。

### 9.2 Loss 继续留在平移后的坐标里

代回 loss，有：

$$
L
=
\operatorname{LSE}(\mathbf z)-z_y
=
\log\sum_j e^{z_j-m}-(z_y-m)
$$

看 `[0,-1000]`：$m=0$，指数和在 float64 下约为 $1$，对数约为 $0$，真实类别平移后的分数为 $-1000$。因此 loss 约为 $0-(-1000)=1000$，结果有限。

这条式子还避免了另一种精度损失。若两个类别分数都是 `1e16`，理论 loss 是 $\log 2$；先算 LSE，再减去 `1e16`，那个很小的 $\log 2$ 可能在大数相加时被舍掉。**直接在 shifted logits 上算 loss，就不必先加回大数、再减掉大数。**

`stable_logsumexp` 是你要独立完成的一个函数；`cross_entropy_from_logits` 可以使用同一数学思路，但别为了调用前者而重新引入这次“大数相加再相减”。函数复用要服从数值含义。

[SciPy 的 log_softmax 文档](https://docs.scipy.org/doc/scipy/reference/generated/scipy.special.log_softmax.html)也直接对比了“先 softmax 再 log”与稳定计算对数概率的结果；[logsumexp 文档](https://docs.scipy.org/doc/scipy/reference/generated/scipy.special.logsumexp.html)可核对稳定 reduction 的用途。这里只作为查证，不需要为了本课另装 SciPy。

## 10. 从你的 batch probability 接到 batch loss

你 R1 的 `stable_softmax` 支持沿指定轴处理多维数组；本课新增的 loss 先收窄到最常见的分类 batch：

```text
logits [B,C]：B 条输入，每条 C 个类别分数
labels [B]：第 b 条输入的真实类别下标 labels[b]
```

**先沿类别算出每条输入的 loss，再沿 batch 求平均。** 这两次 reduction 处理不同对象。

对第 $b$ 行，设 $m_b=\max_c z_{b,c}$：

$$
\ell_b
=
\log\sum_{c=0}^{C-1}e^{z_{b,c}-m_b}
-
(z_{b,y_b}-m_b)
$$

结果是 `[B]`：每条输入一个数。然后：

$$
L=\frac{1}{B}\sum_{b=0}^{B-1}\ell_b
$$

> 一共有 B 个输入/样本，那么我要为这一个 batch 算出来一个 Loss，再去调整参数，所以整体的 Loss 等于每个输入的 loss 的均值。

结果是一个 scalar（标量）。你已经修好的 `axis` 与 `keepdims` 在这里仍然适用：中间参与广播的量保留类别轴，最后对外返回每行结果时再去掉已聚合的轴。

无需推广到任意维 label、分割任务或带权重 loss；先把这条二维 batch 链完成。

### 11.3.1 axis out of range 啥意思

意思是：**`axis` 必须指定这个数组实际存在的一条轴。** LSE 是 log-sum-exp（指数求和后取对数），这里的 `axis` 指沿哪一维计算。

例如数组的 shape 是 `(2, 3)`，只有两条轴：

| axis | 对应维度 |
|---|---|
| `0` 或 `-2` | 第一维，大小为 2 |
| `1` 或 `-1` | 第二维，大小为 3 |

因此：

```python
axis=1    # 合法
axis=-1   # 合法
axis=2    # 不合法：没有第三条轴
axis=-3   # 不合法：负索引也超出了范围
```

**`axis out of range` 就是“轴编号超出范围”。** 对一个 `ndim=n` 的数组，合法整数轴满足：

$$
-n\leq \text{axis}<n
$$

`1.5`、`"1"` 这类不是整数轴，也不符合这条接口要求。

## 13. 对你这版实现，为什么无需添加 epsilon

你的 R1 没有往 denominator 加 epsilon，这是合理的：每组至少有一个 maximum 项，平移后它的指数为 `1`，所以本课合法输入的指数和不会因为所有项都下溢而变成 `0`。

§9 的问题发生在正确类别的极小概率，而不是分母没有值。若把它裁到 `1e-12`：

```python

```

那么真实应约为 `1000` 的 loss，会被截成约 `27.63`。它避免了 log(0)，却改变了你想衡量的量。

## 14. T6 最终收口，只检查新增长出来的部分

## 15. 从你的两个消费者走向 AI Infra

你现在已有 T5 sampler 和本次的 stable probabilities；§11 还会补另一条训练计分路径：

```text
model -> logits
            |
            +-> stable probabilities -> T5 sampler / argmax
            |
            +-> logits + true labels -> stable cross entropy
```

到 LLM inference（大语言模型推理）中，候选项从三种动物变成整个词表，链仍然一致：

```text
hidden state（模型算出的当前表示）
-> vocabulary projection（映射成每个词元的分数）
-> logits [batch,vocab]（每条输入、每个候选词元一个分数）
-> temperature / filtering（调整分布集中程度、筛选候选项）
-> 稳定的概率或对数概率计算
-> sampler -> 下一个 token（词元）
```

你的 `copy`、减 maximum、`exp` 与 `sum` 会创建或遍历中间数组。词表很大时，这些动作才会进一步成为 memory bandwidth（内存带宽）、kernel launch（启动算子）和 fusion（合并算子、减少中间读写）的问题。

当前没有测出这些动作就是瓶颈，不要求你现在优化。先保留一个数值正确、轴含义明确的 reference（参考实现），后续性能版本才能与它核对。
