# Part 1：一个数学上正确、计算机里却会坏掉的公式

## 0. 今天要修复什么

你在 T5 已经写出 `sample_categorical(probabilities, sample_count, rng)`：传入 `[0.2, 0.3, 0.5]`，返回一串 `0/1/2` 类别下标；再统计它们的频率。你也修正了候选数量，现在它由概率向量的长度决定。

**T6 解决这一步之前的问题：模型给出的是分数，怎样把分数变成采样器能使用的概率？** 原来的采样器已经通过，不需要重写。

分类模型可能输出：

```text
[1000.0, 1001.0, 1002.0]
```

这三个数还不是 probabilities，而是模型给三个 classes 的 raw scores。这种对象叫 logits（未经概率归一化的原始分类分数）。

我们希望把 logits 转成一组非负、总和为 `1`、保留 score 排序的 probabilities。Softmax 的数学公式能做到，但若直接计算 `exp(1002)`，`float64` 也会 overflow（上溢，结果超过可表示范围）。

今天把这条链串清：

```text
logits
-> softmax probabilities
-> correct-class probability
-> cross-entropy loss
```

同时回答：为什么同一个数学公式，必须换一种等价写法才适合 floating-point computer。

## 1. Softmax 为什么自然出现

先用一个能直接算完的例子。三个分数是 $[0,0,\log 2]$，取指数得到 $[1,1,2]$；总和是 $4$，分别除以 $4$，得到 $[0.25,0.25,0.5]$。每项非负，总和为 $1$，较大的分数得到较大的概率。这就变成了你在 T5 已经会采样的对象。

指数函数满足 $e^z>0$，先对每个 score 取指数：

$$
u_i=e^{z_i}
$$

再除以所有指数之和：

$$
p_i
=
\frac{e^{z_i}}
{\sum_{j=1}^{C}e^{z_j}}
$$

$C$ 是 class count。于是：

$$
p_i>0,
\qquad
\sum_{i=1}^{C}p_i=1
$$

这个 operation 叫 softmax（软最大归一化）。它把 scores 映射成 categorical probabilities，但不会把最大项强行变成 `1`。

这里 $C$ 来自输入的类别数，和你现在 `range(len(probabilities))` 的含义相接。三项只是例子；两类、四类仍使用同一个归一化规则。

## 2. 数学正确为什么不等于数值安全

直接照公式实现：

```python
def naive_softmax(logits: np.ndarray) -> np.ndarray:
    exponentials = np.exp(logits)
    return exponentials / np.sum(exponentials)
```

输入 `[1,2,3]` 时通常工作。输入 `[1000,1001,1002]` 时：

```text
np.exp(1000) -> inf
inf / inf      -> nan
```

`inf` 是 infinity（无穷表示）；`nan` 是 not-a-number（未定义数值结果）。问题不在 softmax 定义，而在 intermediate values 超出 dtype 范围。

另一端也可能 underflow（下溢）：极小正数被舍入成 `0`。若随后计算 `log(0)`，结果会变成 `-inf`。

数值程序必须同时关心：

```text
最终数学值
中间值是否 representable
等价表达在 floating-point 下的误差
```

## 3. 找到稳定写法所需的不变量

给所有 logits 同时加 constant $c$：

$$
\frac{e^{z_i+c}}
{\sum_j e^{z_j+c}}
=
\frac{e^ce^{z_i}}
{e^c\sum_j e^{z_j}}
=
\frac{e^{z_i}}
{\sum_j e^{z_j}}
$$

因此：

$$
\operatorname{softmax}(\mathbf z)
=
\operatorname{softmax}(\mathbf z+c)
$$

这叫 translation invariance（整体平移不变性）。我们可以先把整组 logits 平移到更安全的范围，再取指数。

先停在这里。你已经知道：

```text
所有 logits 必须减同一个值
平移后 probabilities 不变
希望平移后的最大 exponent 不再溢出
```

## 4. Batch 情况先明确 axis

若 logits shape 是 `[B,C]`：

```text
B：batch size
C：class count
```

每一行是一条 sample 的 class scores。归一化必须沿 class axis，即 `axis=-1`：

$$
\sum_{c=1}^{C}p_{b,c}=1
\quad
\text{for every }b
$$

若沿 batch axis 归一化，数值也可能总和为 `1`，但含义变成“同一 class 在不同 samples 间竞争”。Axis 是 correctness contract，不只是 NumPy 参数。

## 5. 开工前只需要这些 API

```python
np.exp(values)
np.max(values, axis=-1, keepdims=True)
np.sum(values, axis=-1, keepdims=True)
np.log(values)
np.isfinite(values)
np.testing.assert_allclose(actual, expected, rtol=..., atol=...)
```

`keepdims=True` 保留 reduction axis 为长度 `1`，让 `[B,1]` 可以 broadcast 回 `[B,C]`。这里只解释 shape，不给稳定函数的完整组合。

# Part 2：Round1，独立找到稳定 probability path

## 6. 程序用途与 contract

文件：`stable_softmax.py`

今天造的是一份 **naive vs stable numerical experiment（普通实现与稳定实现的数值对照实验）**。两个 functions 完成相同的数学任务，但 floating-point execution 不同：

```text
ordinary logits
├─ naive_softmax  -> probabilities
└─ stable_softmax -> probabilities
                    两者应接近

extreme logits
├─ naive_softmax  -> 预期出现 non-finite
└─ stable_softmax -> finite probabilities，sum 约等于 1
```

Round1 先只闭合这张对照图。闸门后再增加第二条程序链：

```text
logits + correct-class label
-> stable logits-space calculation
-> cross-entropy scalar loss
```

对象角色：

| 对象 | 角色 |
|---|---|
| `logits` | model 产生的 raw class scores |
| `naive_softmax` | logits -> probabilities 的数学 operation |
| `stable_softmax` | 同一数学 operation 的数值稳定实现 |
| `cross_entropy_from_logits` | 闸门后加入的 scalar loss function |

`naive_softmax` 与 `stable_softmax` 都不是 model，也不是 optimizer；它们只是同一 operation 的两种 floating-point implementation。Round1 的认知墙是怎样找到稳定等价写法，不是猜程序为什么同时需要两个 functions。

先看 caller 怎样比较两条路径：

```python
ordinary = np.array([1.0, 2.0, 3.0], dtype=np.float64)

naive = naive_softmax(ordinary)
stable = stable_softmax(ordinary)

np.testing.assert_allclose(naive, stable, rtol=1e-12, atol=1e-12)
```

现在再给 public signatures；稳定实现内部怎样组织 shift 仍由你独立完成：

```python

    ...


def stable_softmax(logits: np.ndarray, axis: int = -1) -> np.ndarray:
    ...
```

输入：

```text
floating ndarray
至少 1-D
目标 axis 长度 > 0
所有 logits finite
```

输出：

```text
shape 与 input 相同
所有 values finite 且非负
沿 axis 的 sums 约等于 1
不修改 caller input
```

你的 T5 已经证明了“概率 -> 样本”这半条链。今天把注意力放在 **shape 不变、类别轴归一化、极端分数仍能给出有限结果**；先检查输出 probabilities，不必再跑百万次采样来验证 T5 的部分。下面固定 cases 用三类展示数值现象，不把函数限制为三类。

固定 cases：

```python

extreme = np.array([1000.0, 1001.0, 1002.0], dtype=np.float64)

        [1.0, 2.0, 3.0],
```

# Part 3：从 stable probability 继续走到 stable loss

## 7. 为什么减 maximum

对一组 logits 选择：

$$
m=\max_i z_i
$$

计算：

$$
p_i
=
\frac{e^{z_i-m}}
{\sum_j e^{z_j-m}}
$$

所有 shifted logits 满足 $z_i-m\le0$，最大的 exponential 正好是 $e^0=1$，其余项位于 $(0,1]$。这直接切断 positive overflow。

```text
[1000,1001,1002]
-> subtract 1002
-> [-2,-1,0]
-> exp approximately [0.1353,0.3679,1.0]
```

这一步值得停下来读：减去 `1002` 后，最大的 shifted logit 变成 `0`，所以最大的 exponential 恰好是 $e^0=1$；其余 logits 更小，对应 exponential 都落在 $(0,1)$。原先会溢出的三个巨大中间值，现在全部变成可表示的小数，而最后 probabilities 没有改变。

减 mean 虽然也保持 softmax 不变，却不能保证最大 shifted value 小于等于 `0`。减 maximum 同时利用了不变量与指数范围。

Batch 中 maximum 必须逐行计算：

```python
maximum = np.max(logits, axis=axis, keepdims=True)
shifted = logits - maximum
```

## 8. 从 correct-class probability 推出 cross entropy

这里的正确类别 $y$ 来自数据中的真实答案，例如已知这张图片属于类别 `2`。你在 T5 得到的 samples 是按概率随机抽出的类别；**今天的 label（真实类别标签）是固定答案，用来评价模型分给正确类别的概率**。计算 loss 时不需要先调用采样器。

假设正确 class index 为 $y$，模型分给它的 probability 是 $p_y$。我们希望：

```text
p_y 接近 1 -> loss 接近 0
p_y 接近 0 -> loss 很大
```

Negative log-likelihood（负对数似然）满足：

$$
L=-\log p_y
$$

One-hot target 下的 cross entropy（交叉熵）是：

$$
L
=
-\sum_{c=1}^{C}y_c\log p_c
$$

只有正确 class 的 $y_c=1$，因此退化成 $-\log p_y$。其他 classes 仍通过 softmax denominator 影响 $p_y$。

## 9. Stable softmax 后直接 `log` 仍可能失败

若某项 probability 因 underflow 变成 `0`，`-np.log(0)` 仍是 `inf`。更稳定的路径是从 logits 直接计算 log probability。

定义 log-sum-exp：

$$
\operatorname{LSE}(\mathbf z)
=
\log\sum_j e^{z_j}
$$

利用 $m=\max_j z_j$：

$$
\operatorname{LSE}(\mathbf z)
=
m+\log\sum_j e^{z_j-m}
$$

于是：

$$
\log p_y
=
z_y-\operatorname{LSE}(\mathbf z)
$$

$$
L
=
\operatorname{LSE}(\mathbf z)-z_y
$$

这条路径不需要先 materialize（实体化）完整 probabilities 再取 log。Framework 的 fused cross-entropy kernel 也围绕相同数值思想组织。

## 10. Batch loss 的 shape

输入：

```text
logits [B,C]
labels [B]，integer class indices
```

每行得到一个 loss：

$$
\ell_b
=
\operatorname{LSE}(\mathbf z_b)-z_{b,y_b}
$$

最后沿 batch 求 mean：

$$
L
=
\frac{1}{B}\sum_{b=1}^{B}\ell_b
$$

Class reduction 与 batch reduction 是两次不同 operation。不要只写“对 logits 求和”而不说明 axis。

## 12. 常见分布放回正确位置

```text
binary classification
-> one logit -> sigmoid -> Bernoulli probability

multiclass / next-token prediction
-> C logits -> softmax -> categorical probabilities

continuous target with Gaussian assumption
-> model predicts distribution parameters
-> Gaussian likelihood
```

T6 不展开完整 maximum-likelihood theory。只要看见：loss 常来自“让 observed target 在 model distribution 下更可能”。

# Part 4：收口

## 13. 为什么不把 epsilon 当通用修复

有人会写：

```python
safe_probability = np.clip(probability, 1e-12, 1.0)
loss = -np.log(safe_probability)
```

Clipping 可作为某些 API 的保护，但它改变了原 probability。若 logits 在手，stable log-sum-exp 是更忠实的路径。给 denominator 随便加 epsilon 同样改变 normalization。

数值稳定性的核心不是“看到除法就加小数”，而是找到数学等价、但 intermediate values 更安全的表达。

## 15. 与 AI Infra 的连接

你现在已有后半段的 sampler；T6 为它补前半段的 scores-to-probabilities 数值参考。两者接起来才是一条完整的分类采样路径。

LLM inference 中：

```text
hidden state
-> vocabulary projection
-> logits [batch,vocab]
-> temperature / filtering
-> stable normalization or log-probability
-> sampler
```

Vocabulary 很大，因此 softmax 同时涉及 reduction axis、intermediate Tensor bytes、kernel launch、memory bandwidth、fusion 与 distributed communication。当前先建立正确 reference；以后所有 fast path 都要能回到这里对质。
