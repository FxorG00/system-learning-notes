# Part 1：从回归一个数，走到选择一个 class

## 0. 今天解决两个问题

T7 的 model 输出一个连续数值。现在数据属于三个 classes：

```text
class 0
class 1
class 2
```

我们需要 model 为每条 sample 产生三个 scores，再回答两个层次的问题：

1. **计算层**：怎样从 `[B,D]` features 得到 `[B,C]` logits，训练出一个三分类器？
2. **实验层**：训练集表现很好时，怎样证明 model 对没见过的数据也有用？

今天的完整链是：

```text
features
-> logits
-> probabilities
-> cross-entropy loss
-> gradients
-> parameter update
-> validation-based model choice
-> one-time test evaluation
```

## 1. 为什么每个 class 需要一个 score

设 input dimension 为 $D$，class count 为 $C$：

```text
X [B,D]
W [D,C]
b [C]
```

Linear classifier：

$$
Z=XW+b
$$

$Z$ shape 是 `[B,C]`。第 $b$ 行描述第 $b$ 条 sample；第 $c$ 列是它对 class $c$ 的 score。

这些 scores 叫 logits（未经概率归一化的分类分数）。它们可以是任意实数，不要求位于 `[0,1]`。

T6 的 stable softmax 沿 class axis 把每行 logits 变成 probabilities：

$$
P_{b,c}
=
\frac{e^{Z_{b,c}}}
{\sum_{j=1}^{C}e^{Z_{b,j}}}
$$

Prediction（预测类别）是：

$$
\hat y_b=\arg\max_c Z_{b,c}
$$

对 softmax 前后取 `argmax` 结果相同，因为 exponential 和 normalization 都不改变同一行内的排序。

## 2. Binary logistic 与 multiclass softmax 的关系

Binary logistic regression（二分类逻辑回归）只需一个 logit $z$，通过 sigmoid：

$$
\sigma(z)=\frac{1}{1+e^{-z}}
$$

得到 class `1` 的 probability，class `0` probability 是 $1-\sigma(z)$。

Multiclass softmax regression（多分类 softmax 回归）为每个 class 保留一个 logit，再统一归一化。两者都不是用 linear regression 的数值大小直接当类别；它们先建立 probability model，再用 loss 训练。

当前主产出直接做三分类。Binary logistic 只需理解对应关系，不另写一套程序。

## 3. Cross entropy 在训练什么

对第 $b$ 条 sample，真实 class index 为 $y_b$。Per-sample loss：

$$
\ell_b=-\log P_{b,y_b}
$$

Batch mean：

$$
L
=
\frac{1}{B}\sum_{b=1}^{B}\ell_b
$$

如果 model 给正确 class 高 probability，loss 小；若自信地相信错误 class，正确 class probability 接近 `0`，loss 很大。

Accuracy 只关心 argmax 是否正确。下面两组 probabilities 都预测 class `0`：

```text
[0.51,0.49,0.00]
[0.99,0.01,0.00]
```

若真实 class 是 `0`，accuracy 都是 `1`，但第二组 confidence 更强、loss 更小。训练看 loss，最终任务解释通常同时看 loss 与 accuracy。

## 4. Softmax + cross entropy 的 gradient

对一条 sample，loss 对 logits 的 gradient 有一个非常紧凑的形式：

$$
\frac{\partial \ell}{\partial z_c}
=
p_c-\mathbf 1[c=y]
$$

直觉：

```text
错误 classes：gradient 是正 probability，update 会压低它们
正确 class：gradient 是 p_y-1，update 会抬高它
```

Batch 写成：

```text
dZ [B,C] = (probabilities - one_hot(labels)) / B
```

再沿 linear layer 反传：

$$
\frac{\partial L}{\partial W}=X^T dZ
$$

$$
\frac{\partial L}{\partial b}
=
\sum_{b=1}^{B}dZ_b
$$

Shape：

```text
X.T [D,B] @ dZ [B,C] -> dW [D,C]
sum dZ over batch       -> db [C]
```

这条 gradient 不要求你重新从头推导 softmax Jacobian 的每个元素，但要能用 T4 的 chain-rule 模型解释它为什么同时影响全部 classes。

## 5. 先准备一份能暴露 workflow 的 dataset

建议每类中心：


# Part 3：训练成功以后，怎样判断它真的有用

## 9. Training set 只能回答“见过的数据学得怎样”

若一直根据同一批 samples：

```text
更新 parameters
选择 learning rate
选择 regularization
决定训练多久
```

model 可能越来越适合这批数据，却不一定适合新数据。这种从已见数据推广到未见数据的能力叫 generalization（泛化）。

训练集 accuracy 高，只证明 optimization 至少在当前数据上有效。它不是最终泛化证据。

## 10. Train、validation、test 的职责

### Training set

参与 gradient update：

```text
forward
-> loss
-> gradient
-> parameter update
```

### Validation set

不参与 parameter gradient。它用于选择：

```text
learning rate
regularization strength
training steps
feature design
model variant
```

这些 choices 叫 hyperparameters（超参数）：它们不由本轮 backward 直接学习，而由外层实验选择。

### Test set

所有设计与配置确定后只打开一次，用来估计最终方案对未见数据的表现。

```text
train：fit parameters
validation：choose configuration
test：report final generalization
```

若反复根据 test result 调配置，test 已经在事实上变成 validation，不能再作为独立最终证据。

## 11. Split 必须发生在 preprocessing 之前

例如 feature standardization 需要 mean/std：

```text
先 split
-> 只用 train 计算 mean/std
-> 同一组 train statistics 变换 validation/test
```

若先用完整 dataset 计算统计量，validation/test information 已经流进 training pipeline。这叫 data leakage（数据泄漏）：评估阶段的信息影响了训练。

Synthetic dataset 当前可不做复杂 preprocessing，但这条顺序必须写入 workflow。

## 12. Underfitting 与 overfitting 从两组表现判断

Underfitting（欠拟合）：

```text
train performance 差
validation performance 也差
```

Model 连训练集的主要规律都没学到，常对应 high bias（高偏差）。

Overfitting（过拟合）：

```text
train performance 很好
validation 明显更差
```

Model 过度适应训练样本细节，常对应 high variance（高方差）。

只有 validation 差，不能直接喊 overfitting；还要看 train/validation gap 和任务可达到的 baseline。

T13 会用真实 curves 深入观察。T8 只建立诊断语言。

## 13. L2 regularization 改变 model 愿意使用多大的 weights

在 loss 后加入：

$$
L_{\text{reg}}
=
L_{\text{data}}
+\frac{\lambda}{2}\lVert W\rVert_2^2
$$

Gradient 多出：

$$
\frac{\partial L_{\text{reg}}}{\partial W}
=
\frac{\partial L_{\text{data}}}{\partial W}
+\lambda W
$$

Bias 通常不放进这项 penalty。

$\lambda$ 小时接近未正则化；太大时 weights 被压得过小，model 可能 underfit。正确值由 validation set 选择，而不是看到 overfitting 就无限加大。

## 14. Round2：把 V1 放进固定 workflow

将 dataset deterministic split 为：

```text
train
validation
test
```

先固定三个候选 configurations，例如：

```text
learning rate
training steps
L2 lambda
```

对每个 candidate：

```text
只在 train 上 fit
在 validation 上计算 loss/accuracy
记录结果，不看 test
```

选择 validation 最好的 configuration 后，先固定最终 policy。可以直接采用选中的 checkpoint；也可以事先约定用 `train + validation` 重新训练一次，但此后不能再根据 test result 改配置。最终只对 test 评估一次，并把采用的 policy 写清楚。

为了保持工作量受控，只比较 3~4 个有理由的 candidates。不要把 T8 变成无边界 tuning。

## 15. Confusion matrix 看见“错在谁身上”

Accuracy 把所有错误压成一个比例。Confusion matrix（混淆矩阵）保留真实 class 与 predicted class 的组合：

```text
rows：true class
columns：predicted class
```

实现可用：

```python
matrix = np.zeros((class_count, class_count), dtype=np.int64)
for truth, predicted in zip(labels, predictions):
    matrix[truth, predicted] += 1
```

必须满足：

```text
matrix shape [C,C]
all entries >= 0
matrix.sum() == sample_count
diagonal sum == correct prediction count
```

它能说明哪些 classes 经常互相混淆，比只看总 accuracy 更接近 error analysis。

## 16. Accuracy 与 loss 各自回答什么

```text
accuracy：最终 argmax decision 对了多少
loss：model 给真实 class 分配了多少 probability
```

Accuracy 不敏感于 confidence；loss 对极度自信的错误非常敏感。训练过程中两者都应记录：

```text
loss 用于 optimization 与概率质量
accuracy 用于任务层 decision
```

不要把较低 loss 自动翻译成“所有业务指标都更好”。Metric 必须对应真实决策代价。

# Part 4：Theory Gate 1 与系统连接

## 17. 最小验证矩阵

Function-level：

```text
logits shape/value
stable loss finite
analytic gradient vs finite difference
predictions range
confusion matrix invariants
```

Workflow-level：

```text
train-only parameter updates
validation-only configuration choice
test opened once
preprocessing statistics fit on train only
固定 seed/config 可复现
```

这两层都重要。函数全对，不代表 workflow 没有 leakage；workflow 写得漂亮，也不能掩盖 gradient 错误。

## 19. 与 AI Infra 的连接

Training pipeline：

```text
dataset version
-> split policy
-> preprocessing state
-> configuration
-> trained parameters
-> validation evidence
-> final test report
```

Serving pipeline：

```text
model artifact
-> input schema
-> forward logits
-> decision/sampling policy
-> response
```

一个可部署 model 不只是 weights。它还需要 feature schema、normalization state、class mapping、model version 与 evaluation evidence。T10 的 `state_dict` 会接住其中的 parameter/buffer artifact，后续 inference server 再接住运行边界。
