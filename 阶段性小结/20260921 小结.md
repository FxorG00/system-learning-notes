## 五、你的学习方式也发生了变化

### 5.1 你不再被动接受教程

你会主动指出：

```text
接口用途没有讲清
contract 缺少调用场景

测试只是 dirty work，还是承载关键机制
某段内容又臭又长但没有新增量
```

这不是“挑教程毛病”，而是在形成工程判断。你已经能判断哪些信息是：

```text
必要 contract
实现选择
高价值边界
重复提醒
机械样板
```

### 5.2 你对 dirty work 的判断更成熟了

你不是简单拒绝测试，而是在区分：

```text
必须亲手做：
核心状态机、第一次 representation、关键边界、失败解释

可以交给 Codex：
批量 GoogleTest scaffold、重复 case、CMake glue、机械检查
```

最近 HTTP parser 很像算法竞赛的大模拟。这样的核心训练在 HTTP 和 RESP 各做一次有价值；以后不应该无限重复，而应把新增量转向 integration、ownership、concurrency、performance 和 trade-off。

### 5.3 需要继续警惕的倾向

你推进很快，但也有三个风险：

1. **累的时候容易把所有 test 都归为 dirty work。** 有些确实可以代写，但承载 state transition 或 independent oracle 的最小实验不能全部省掉。
2. **代码修好了，note 可能仍保留旧模型。** 验收必须继续同时看 source 和 note，避免以后复习时被旧文字带偏。
3. **追求每天完成容易压缩消化时间。** Week9 以后一天不是自然日要求；真实 blocker 多用半天或一天很正常。
